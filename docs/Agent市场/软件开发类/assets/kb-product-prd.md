# kb-product-prd · 产品需求与验收

> 用途：需求事实源——PRD、用户故事、验收标准、变更记录。  
> 挂载：PM、架构、QA、集成；开发读验收与范围。  
> 规则：范围变更用 CR 追加，不改历史原文；AC 编号全链路引用。

---

# 1. PRD 标准模板

```markdown
# <功能名> PRD

| 项 | 内容 |
|---|---|
| 版本 | v1.0 |
| 日期 | YYYY-MM-DD |
| 作者 | |
| 状态 | 草稿 / 评审中 / 已定稿 |

## 1. 背景与问题
## 2. 目标
## 3. 非目标（明确不做）
## 4. 用户与场景
## 5. 用户故事
## 6. 功能范围
## 7. 验收标准（AC）
## 8. 交互/数据要点（可链到契约）
## 9. 风险与依赖
## 10. 优先级与里程碑
## 11. 开放问题（待确认）
```

## 写作规则

1. **非目标**必须写；防止范围膨胀。  
2. 验收标准可测，禁止「体验好」「性能高」。  
3. 不确定事实标「待确认」，禁止臆造业务数据。  
4. 与契约冲突时，以评审后的契约为准并回写 PRD。

# 2. 用户故事与验收写法

## 用户故事格式

```text
作为 <角色>
我希望 <能力>
以便 <价值>
```

示例：

```text
作为 运营
我希望 导出带统计字段的订单报表
以便 对账时不用二次计算
```

## 验收标准（AC）

### Given/When/Then

```text
AC-1 导出成功
Given 用户已登录且有导出权限
When 选择时间范围并点击导出
Then 生成 xlsx，且包含 orderCount/amountSum 字段
```

### 清单格式

```text
AC-1 [ ] 空结果时提示「无数据」且不生成文件
AC-2 [ ] 超过 10 万行提示分批或异步
AC-3 [ ] 无权限用户按钮置灰并有说明
```

## 规则

1. AC 编号稳定，全链路引用（用例/交付包）。  
2. 每条 AC 只验证一件事。  
3. 必须含失败/边界路径。  
4. AC 与接口契约字段名可对上。

# 3. 变更 / 裁决记录（CR）

```markdown
# CR-<yyyymmdd>-<seq> <标题>

| 项 | 内容 |
|---|---|
| 日期 | |
| 提出人 | |
| 影响 PRD | |
| 状态 | 提出 / 采纳 / 拒绝 / 延后 |

## 变更内容
## 原因
## 影响（范围/工期/风险）
## 决策
## 连带修改（AC/契约/任务）
```

**纪律**：不改历史 PRD 原文；群聊导致范围变化必须落 CR；拒绝也留痕。

# 4. 样例需求：导出统计字段（练习用）

## 背景

运营对账时导出订单，需自带统计列，避免二次计算。

## 目标

- 导出文件含 `orderCount`、`amountSum`
- 空结果有明确提示

## 非目标

- 不做在线图表
- 不改导入格式

## 用户故事

作为 运营，我希望 导出报表自带统计列，以便 对账一次完成。

## 验收

- AC-1 导出成功且含 orderCount、amountSum
- AC-2 空结果提示「无数据」
- AC-3 无导出权限时不可点击

## 开放问题

- 超大导出是否走异步任务？（待产品裁决）
