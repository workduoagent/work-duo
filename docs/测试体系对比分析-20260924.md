## 三、已落地的吸收改动（本轮）

1. **通用信号层**：`runOneCase` 从 trace events 提取 `rec.signals = {hasPlanGenerated, planSteps, toolCalls[], writeCount, sensitiveCount, errorCount}`——任何用例从此都能做链路断言（不只 H 系列）。
2. **H 系列 6 用例**（scene H / phase 7）：H-M1 快路径、H-M2 灰色地带、H-M3 token 预算、H-M4 PathGuard 拒绝、H-M5 敏感留痕、H-M6 越界 delete。
3. **noWorkspace 支持**：CASES 可声明 `noWorkspace: true`（SIMPLE_CHAT 类用例不绑工作空间，测真实快路径）。

### 三个失败的归因（均为提示遵守度，非引擎 bug）

1. **D1-3 灰色地带**：——agent 对「分析语气」写了 3 个文件。与我的 H-M2（write=0）结论矛盾的根因：**H-M2 用 noWorkspace（无工作空间可写），对方用例绑了 workspace**——工作空间的存在本身诱导「顺手落盘」。
2. **D2-4 纯问答不落盘**：（写了 7 个）+ reply 为「暂定完成」——**planner.rs「知识问答降耗约定」被违反**（只约束了规划拆步，未约束执行器的自由落盘）；token=7421 反而达标。
3. **D3-1 单步闭环**：——1-2 轮的简单任务也没交期望产物（「做了活不交件」家族在简单任务同样存在）。

**共同候选修法**（Planner/执行提示层，Rust+重启）：无产物要求（success_criteria 空 且 expectedArtifacts 空）的分析/问答类步骤 → 执行器禁止写工作空间文件、直接回复。

**方法论沉淀**：对方用例的断言粒度（no_workspace_write/no_files 事件级）抓到了我 H-M2 漏掉的行为差异——**测试环境本身（有无 workspace）会改变 agent 行为**，对照实验必须控制变量。
