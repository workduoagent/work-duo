## 三、仍然说破的口径问题（延续 09-22 的诚实）

1. **题库仍是自己的卷子**：自造坏种子证明了「修复能力存在」，但 SWE-bench 的真实差距在「真实 repo 的上下文规模与 issue 模糊度」。判分基建已就绪，**换题即可出分**——这是下一步最高杠杆。
2. **模型红利与工程分要分账**：本轮主测模型 DeepSeek-V4.1-Flash 表现稳定，分数里有模型成分；换弱模型的衰减幅度未系统测（09-22 的 15 倍时延差提醒仍在）。
3. **44 用例仍是「已知分布」**：真实用户的用法分布长尾得多；L4 的证据只能来自运营。
4. Java/多语言纠错、OS 级沙箱隔离强度——**明确未测**，不因 Python 全绿而外推。

## 四、更新后的追赶路线（09-24 版，按杠杆率排序）

### 批次 C'：真实化题库（最高杠杆，基建已就绪）
- 从真实 repo bug 报告/回归测试抽取 10-20 题（脱敏），套现成 seeds/ 包体系 + 判分器。
- 验收：`resolved%` 与公开榜单可比；同时保留自造种子做回归门禁。

### 批次 B'：多语言纠错 + 沙箱补强
- Java 纠错用例（本机 JDK 21 + Maven 3.9 已具备）：需 agent 装配 `execute_command`（非沙箱模式）或 Java 沙箱；Spring Boot 启动报错（端口/Bean/配置）三类种子。
- OS 级沙箱隔离验证（文件逃逸/网络/资源限制）。

### 批次 A'：门禁运营化
- gate 接入发布流程（版本打包前置）；证据目录按版本归档；`resolved%`/产物%作为版本回归指标。

### 批次 D'：L4 继续
- 成本观测（token/费用进 trace 与评分卡）、产物回滚、>30min 连续性、限流。
