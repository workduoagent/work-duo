## 一、查缺补漏：文档中有但前端尚未体现的能力

后端引擎已具备以下能力，但前端 UI 尚未提供对应的可视化或交互入口。

### 1.1 上下文 / 记忆可视化（高优先级）

**背景：** 后端已实现 `wd_mem` 双轨记忆和 `round_compactor` 会话压缩机制，但用户对以下信息完全无感知：
- 当前子任务"看到了"哪些历史信息
- 长会话压缩时，哪些内容被折叠 / 丢弃了

**建议实现：**

在每条用户消息旁增加 **「上下文透镜」** 按钮（图标：🔍），点击后展开浮层，显示：

| 区域 | 内容 | 视觉标识 |
|---|---|---|
| 系统提示摘要 | 当前子任务注入的 system_prompt 核心约束 | 绿色边框卡片 |
| 工作记忆召回 | `wd_mem` 中召回的相关记忆条目列表 | 蓝色时间线 |
| 压缩历史提示 | `round_compactor` 触发裁剪的轮次与原因 | 灰色虚线 + 折叠态 |
| 上下文占比 | 当前消息占可用上下文窗口的比例 | 环形进度条 |

**交互细节：**
- 浮层宽度 480px，右侧滑出（类似 macOS 通知中心）
- 被压缩的历史轮次默认折叠，点击「展开 N 条已压缩记录」后显示摘要
- 当上下文使用率超过 80% 时，环形进度条变为橙色；超过 95% 时变为红色并提示「即将触发压缩」

### 1.2 Token 消耗实时可视化（中优先级）

**背景：** 后端在 `agent-task-done` 事件中携带 `promptTokens` 和 `completionTokens`，但前端没有专门的**成本仪表盘**。

**建议实现：**

**A. 实时 Token 计数器（轻量态）**

放置在对话顶部标题栏右侧或步骤进度条上方：

```
🪙 12.4k / 128k  ·  步骤 2/3  ·  ⏱️ 8.3s
```

- 数字每轮更新，使用等宽字体避免跳动
- 当某步子任务 token 消耗异常（单次超过 8k）时，数字旁显示 ⚠️ 黄色警告标识
- Hover 显示明细：Prompt Tokens / Completion Tokens / 工具定义消耗占比

**B. 任务完成后的成本摘要卡片**

在最终助手消息下方插入一张可折叠的卡片：

```
┌─────────────────────────────────────┐
│ 📊 本次任务消耗  ·  总计 24,832 tokens │
├─────────────────────────────────────┤
│ 意图分类    ████░░░░░░  1,024  (4%)  │
│ 任务规划    ████░░░░░░  1,280  (5%)  │
│ 步骤 1      ████████░░  4,560 (18%)  │
│ 步骤 2      ██████████  8,920 (36%)  │ ← 峰值轮次，高亮标注
│ 步骤 3      ███████░░░  6,240 (25%)  │
│ 其他开销    ██░░░░░░░░  2,808 (12%)  │
├─────────────────────────────────────┤
│ 模型：MiniMax-M3  ·  温度：0.7        │
└─────────────────────────────────────┘
```

### 1.3 附件 / 多模态输入交互（中优先级）

**背景：** `RunAgentTaskInput` 已定义 `attachments?` 字段，但前端 UI 部分完全没有描述附件上传、预览、管理的交互。

**建议实现：**

**A. 拖拽上传区域**

输入框下方增加一个**隐形拖拽感应区**（高度 40px，平时透明，拖拽文件进入时显示虚线边框 + 提示文字「释放以上传文件」）。

**B. 附件标签栏**

已上传的附件以横向标签形式显示在输入框上方：

```
[📄 report.xlsx  12KB] [📊 chart.png  340KB] [📎 +2] [×]
```

- 图片类型：显示 32×32 缩略图
- 文档类型：显示对应图标 + 文件名
- 超过 3 个附件时，折叠为「+N」按钮，点击展开全部
- 每个标签 hover 显示删除按钮（×）

**C. 粘贴板监听**

监听全局 `paste` 事件：
- 用户截图后直接 `Ctrl+V` → 自动提取剪贴板图片，转为附件标签
- 粘贴文本文件内容 → 自动创建临时文本附件

**D. 附件发送策略**

- 小文件（< 50KB）：直接内联到 prompt 中作为文本
- 大文件 / 二进制文件：上传后发送文件路径引用，后端通过 `ReadFileTool` 读取

### 1.4 错误恢复交互（高优先级）

**背景：** 后端强调「失败永远降级不崩溃」，但前端监听中只有 `agent-task-error` 和 `step_finished`（status 可能为 failed），缺少**用户介入恢复**的 UI。

**建议实现：**

**A. 步骤级失败恢复（PlanStepsBar 内嵌）**

当某步骤失败时，该步骤卡片从「运行中」变为「受阻」状态（红色左侧边框 + ⚠️ 图标），并展开显示操作面板：

```
┌──────────────────────────────────────────────┐
│ ⚠️ 步骤 2：生成 Excel 报表                      │
│    受阻原因：连续 2 轮工具调用失败                │
│    最后错误：ModuleNotFoundError: No module    │
│             named 'openpyxl'                   │
├──────────────────────────────────────────────┤
│ [🔄 重试此步]  [⏭️ 跳过并继续]  [✏️ 手动接管]   │
└──────────────────────────────────────────────┘
```

- **重试此步**：调用后端重新执行当前 `run_subtask`，保留前序步骤产物
- **跳过并继续**：将失败步骤的 `summary` 设为「用户要求跳过此步骤」，继续执行后续步骤
- **手动接管**：弹出 Monaco Editor（或轻量代码编辑器），让用户直接修改产物 / 代码，点击「标记为完成」后流水线继续

**B. 全局错误诊断面板**

当收到 `agent-task-error` 时，在对话区域中央弹出诊断面板：

```
┌─────────────────────────────────────────────────────┐
│ ❌ 任务执行异常                                       │
├─────────────────────────────────────────────────────┤
│ 错误链：                                             │
│   1. HTTP 400 @ call_llm_stream (步骤 2, 轮次 3)     │
│      → tool result's tool id not found               │
│   2. runtime::sanitize_message_sequence 触发修复     │
│      → 补齐 1 条缺失的 tool 结果占位                  │
│   3. 修复后重试仍失败 → 超出最大重试次数               │
├─────────────────────────────────────────────────────┤
│ 建议操作：                                           │
│   • 检查是否有并行工具调用被意外截断                   │
│   • 尝试降低任务复杂度，拆分为多个独立任务             │
├─────────────────────────────────────────────────────┤
│ [📋 复制诊断信息]  [🔄 重新启动任务]  [💬 反馈问题]   │
└─────────────────────────────────────────────────────┘
```

### 1.5 审批流的批量与记忆（中优先级）

**背景：** `ApprovalNotify` 是右下角弹窗，但复合任务可能连续触发多个敏感工具（如先写文件再执行命令），用户会被连续打断。

**建议实现：**

**A. 批量审批模式**

当 3 秒内连续触发同类审批（如两次 `WriteFileTool`）时，合并为一个「批量审批」弹窗：

```
┌─────────────────────────────────────────────┐
│ 🔒 批量审批（2 项待处理）                     │
├─────────────────────────────────────────────┤
│ ☑️ 写入文件：/workspace/output/report.xlsx   │
│    [查看代码] [查看预览]                      │
│ ☑️ 写入文件：/workspace/output/summary.md    │
│    [查看代码] [查看预览]                      │
├─────────────────────────────────────────────┤
│ [✅ 全部允许]  [❌ 全部拒绝]  [🔍 逐项审批]   │
└─────────────────────────────────────────────┘
```

**B. 信任域设置**

每个审批弹窗底部增加复选框：
- 「始终允许对此目录（`/workspace/output/`）的写操作」
- 选择后写入用户偏好配置（SQLite），后续同类操作自动通过

**C. 审批预览增强**

| 工具类型 | 预览内容 |
|---|---|
| `RunPythonSandboxTool` | 语法高亮的代码 + 预计执行时间（基于历史数据估算） |
| `WriteFileTool` | Diff 预览（如果有旧文件）/ 新文件内容预览 |
| `EditFileTool` | 修改前后对比（行级 diff） |
| `ExecuteCommandTool` | 命令拆解 + 风险提示等级（红/黄/绿） |

## 二、UI 优化建议：在现有基础上做精做细

### 2.1 步骤进度条（PlanStepsBar）深度增强

**当前状态：** 标题常显，summary 默认折叠。

**优化方案：**

**A. 微操作日志（工具调用链时间轴）**

每个步骤内部展开后，显示类似 GitHub Actions 的时间轴：

```
● 调用 read_file          (120ms)    ✅ 成功
  └─ 参数：{"path": "/workspace/data.csv"}
  └─ 输出：前 3 行预览...
│
● 调用 run_python_sandbox  (3.2s)     ✅ 成功
  └─ 参数：{"code": "import pandas..."}
  └─ 输出：图表已保存至 /workspace/chart.png
│
○ 等待审批 write_file      (⏸️ 暂停)   ⏳ 等待用户
  └─ 参数：{"path": "/workspace/output.xlsx"}
```

- 点击每条日志可查看**完整输入参数**和**截断后的输出前 10 行**
- 耗时超过 5s 的步骤显示黄色高亮
- 失败步骤显示红色，点击展开错误详情

**B. 步骤产物预览**

步骤 2 生成了 Excel，在步骤卡片内直接显示**前 5 行数据表格预览**：

```
┌─────────────────────────────────────┐
│ 📄 产物预览：report.xlsx              │
├──────┬────────┬────────┬────────────┤
│ 日期 │  开盘   │  收盘   │    涨跌     │
├──────┼────────┼────────┼────────────┤
│ ...  │  ...   │  ...   │    ...     │
│ ...  │  ...   │  ...   │    ...     │
│ ...  │  ...   │  ...   │    ...     │
│ ...  │  ...   │  ...   │    ...     │
│ ...  │  ...   │  ...   │    ...     │
├─────────────────────────────────────┤
│ [在应用中打开]  [复制路径]  [下载]     │
└─────────────────────────────────────┘
```

- 前端通过后端推送的预览数据渲染，无需读取完整文件
- 图片产物显示 200px 高度缩略图
- Markdown 产物显示渲染后的前 200 字符

**C. 步骤间管道线**

用视觉连线表示步骤 1 → 步骤 2 的产物传递关系：

```
步骤 1：数据采集  ──[传递：SOL 近一周价格数据]──>  步骤 2：生成 Excel
```

- 连线 hover 显示传递的 `summary` 内容（前 100 字符）
- 多步骤时形成垂直流水线视觉效果

### 2.2 思考面板分层（Thinking Panel）

**当前状态：** 统一推送 reasoning / content，无分层。

**优化方案：**

**三级思考分层**，用不同图标和颜色区分：

| 层级 | 图标 | 颜色 | 来源 | 内容示例 |
|---|---|---|---|---|
| 🧭 规划思考 | 指南针 | 紫色 | `planner.rs` | 意图分类结果、DAG 规划过程、`goal_summary` |
| 🔧 执行思考 | 扳手 | 蓝色 | `pipeline.rs` | 每轮子任务的 reasoning、工具选择逻辑 |
| 🛡️ 自检思考 | 盾牌 | 橙色 | `runtime.rs` | `sanitize_message_sequence` 修复提示、token 预算预警 |

**交互细节：**
- 每条思考气泡显示**耗时**（如「思考了 1.2s」）
- 默认只展开**当前步骤**的思考，历史步骤的思考折叠为「🧠 思考了 3 轮」，点击展开
- 提供「🔇 隐藏思考过程」开关，减少界面噪音（偏好持久化）
- 自检思考触发时，在对应消息旁闪烁橙色边框 1s 以引起注意

### 2.3 文件产物画廊（FilePathCards 升级）

**当前状态：** 正则识别路径，点击 `openPath`。

**优化方案：**

**A. 产物生命周期管理栏**

在对话区域上方或侧边栏增加**「本次任务产物」**横向滚动栏：

```
📦 本次产物（5）
┌────────┬────────┬────────┬────────┬────────┐
│ 📊     │ 📄     │ 🖼️     │ 📈     │ 📝     │
│ chart  │ report │ viz    │ forecast│ notes │
│ .png   │ .xlsx  │ .html  │ .md    │ .txt  │
│ 340KB  │ 12KB   │ 2.1MB  │ 4KB    │ 1KB   │
└────────┴────────┴────────┴────────┴────────┘
```

- 图片：缩略图（64×64）
- Excel/CSV：表格图标 + 行数标签
- 文本/Markdown：前 50 字符预览
- 代码文件：语言图标 + 行数

**B. 文件操作菜单**

右键菜单或 hover 操作栏：
- **在文件夹中打开**：调用 `openPath`
- **复制绝对路径**：写入剪贴板
- **复制文件内容**：小文件（< 100KB）直接读取复制
- **删除 / 归档**：调用 `ArchiveArtifactTool`，归档后移入「已归档」区域
- **作为附件引用**：点击后自动将路径填入输入框

**C. 文件状态徽章**

| 状态 | 徽章 | 说明 |
|---|---|---|
| 新增 | 🟢 绿色 dot | 本次任务新创建 |
| 修改 | 🟡 黄色 dot | 覆盖已有文件 |
| 沙箱生成 | 🔒 盾牌 | 由 `RunPythonSandboxTool` 生成 |
| 已归档 | 📦 灰色 | 用户手动归档 |

### 2.4 输入框智能化（Input Box Intelligence）

**当前状态：** 拖拽高度、全屏居中。

**优化方案：**

**A. @ 提及系统**

输入 `@` 弹出菜单（类似 Discord/Notion）：

```
@文件        → 列出工作空间内文件，支持模糊搜索
@技能        → 列出可用 Skill，可快速禁用/启用（带复选框）
@记忆        → 召回 wd_mem 中的相关记忆条目
@模型        → 快速切换当前绑定的 LLM
```

- 选择 `@文件` 后，自动注入绝对路径到 prompt，格式：`[文件: /workspace/data.csv]`
- 选择 `@技能` 后，显示当前启用的技能列表，点击可切换开关状态

**B. 快捷指令面板**

输入 `/` 弹出快捷指令：

| 指令 | 效果 |
|---|---|
| `/python` | 自动包裹为「请用沙箱执行 Python：...」 |
| `/debug` | 自动追加「请详细展示每一步的思考过程」 |
| `/simple` | 强制走 `SIMPLE_CHAT` 模式（绕过复合任务规划） |
| `/plan` | 只执行规划阶段并展示 DAG，不执行 |
| `/clear` | 清空当前会话上下文 |

**C. 输入预估**

输入框右下角显示轻量灰色小字：

```
已输入 156 字  ·  预估 ~234 tokens
```

- 当预估超过当前模型上下文窗口的 50% 时，变为黄色提示
- 发送按钮 hover 显示「发送后预计消耗 ~1,200 tokens」

**D. 发送按钮状态**

| 状态 | 图标 | 说明 |
|---|---|---|
| 空内容 | 🚫 禁用 | 按钮灰色不可点击 |
| 有文本 | ➤ 发送 | 标准发送图标 |
| 有附件 | ➤📎 发送+附件 | 组合图标，hover 显示附件数量 |
| 发送中 | ⏳ 旋转 | 禁用状态，显示加载动画 |

### 2.5 消息气泡增强（Message Bubbles）

**A. 消息分支（Branching）**

对任意助手消息，hover 显示操作栏：

```
[🔄 重新生成]  [✏️ 编辑后重新生成]  [📋 复制]  [👍 有用]  [👎 无用]
```

- **重新生成**：从当前上下文重新调用 LLM，生成新回复
- **编辑后重新生成**：弹出内联编辑器，用户可修改当前消息内容后要求重新生成
- 分支后，原消息保留，新消息在下方展开，形成**分支时间线**
- 用户可在分支间切换对比（类似 ChatGPT 的 regenerate 变体选择）

**B. 引用回复**

选中消息中的任意文本，弹出「引用」按钮（类似微信），自动在新输入框中插入：

```
> [引用] 步骤 2 生成的 Excel 包含以下列：日期、开盘、收盘...

请帮我基于这些数据计算移动平均线
```

**C. 代码块增强**

检测消息中的代码块，增加悬浮操作栏：

```
┌────────────────────────────────────────────┐
│ Python                    [复制] [运行] [保存] │
├────────────────────────────────────────────┤
│ import pandas as pd                        │
│ ...                                        │
└────────────────────────────────────────────┘
```

- **复制**：一键复制代码到剪贴板
- **运行**：如果是 Python，调用 `RunPythonSandboxTool` 执行（需审批）
- **保存**：自动调用 `WriteFileTool` 保存为文件（需审批），弹窗让用户选择路径

### 2.6 全局状态栏（Global Status Bar）

在窗口顶部或输入框上方增加一条**细状态栏**（高度 28px，可折叠）：

```
┌─────────────────────────────────────────────────────────────────────┐
│ 🧠 MiniMax-M3  ·  🌡️ 0.7  ·  🟢 沙箱就绪  ·  🌐 延迟 45ms  ·  📋 复合任务 │
│                                                            [▲ 收起] │
└─────────────────────────────────────────────────────────────────────┘
```

| 元素 | 说明 |
|---|---|
| 🧠 模型名 | 当前绑定的 LLM，点击可快速切换 |
| 🌡️ 温度 | 当前 temperature，规划阶段显示 0.0（固定），执行阶段显示实际值 |
| 🟢 沙箱状态 | 绿色=就绪 / 黄色=正在安装依赖（显示进度条）/ 红色=离线 |
| 🌐 延迟 | LLM 网关 RTT，> 500ms 时变黄色，> 2s 时变红色 |
| 📋 任务模式 | `💬 闲聊` / `📋 复合任务 · 步骤 2/3` / `⏸️ 等待审批` |

## 三、创新提议：差异化与前瞻性

### 3.1 🎯 Agent 执行轨迹可视化（Agent Trace View）

**灵感来源：** AgentPrism（2026 年最佳 Agent UI 奖）的透明化设计理念。

**针对 Work Duo 三层流水线定制：**

在侧边栏新增 **「🔍 轨迹」** 标签页，将一次完整的 `run_agent_task` 渲染为**交互式时间轴图**：

```
┌─────────────────────────────────────────────────────────────┐
│ 🔍 执行轨迹：SOL 价格分析任务                                  │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  [🧭 意图分类] ──→ [📋 规划 DAG] ──→ [🔧 执行流水线]          │
│       │                │                  │                 │
│       ▼                ▼                  ▼                 │
│   ┌─────────┐    ┌──────────┐      ┌──────────────┐        │
│   │SIMPLE?  │    │步骤1:采集│      │步骤1: 3轮工具 │        │
│   │→ NO     │    │步骤2:Excel│     │步骤2: 5轮工具 │        │
│   │原因:命中│    │步骤3:预测│      │步骤3: 2轮工具 │        │
│   │复杂关键词│   └──────────┘      └──────────────┘        │
│   └─────────┘                                               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**每个节点可展开，显示：**
- 完整的 LLM 请求 / 响应（可配置是否展示敏感信息）
- Tool Call 详情（参数、输出、耗时）
- Token 消耗、耗时、温度设置
- 消息序列快照（用于调试 `sanitize_message_sequence`）

**诊断模式：**
- 任务失败时，自动切换到轨迹视图并**高亮失败节点**
- 显示错误传播链：哪个 HTTP 请求失败 → 哪条消息序列出错 → 建议操作
- 支持导出为 JSON 或 Markdown 报告

**价值：** 开发者 / 高级用户调试 Agent 的利器，建立「calibrated trust（校准信任）」的核心手段。

### 3.2 🎨 产物画布模式（Artifact Canvas Mode）

**核心理念：** 把「产物管道」和「前序纯文本摘要单向传递」的数据流**可视化**。

**实现方案：**

复合任务执行时，自动切换到**画布视图**（非线性界面，类似 Figma / Excalidraw 的轻量版）：

```
┌──────────────────────────────────────────────────────────────┐
│  🎨 产物画布                                                  │
│                                                              │
│   ┌─────────────┐         ┌─────────────┐                   │
│   │ 📊 data.csv  │────────→│ 📄 report   │                   │
│   │  (步骤1产物)  │         │  .xlsx      │                   │
│   │  7天数据     │         │  (步骤2产物)  │                   │
│   └─────────────┘         └──────┬──────┘                   │
│                                   │                         │
│                                   ▼                         │
│                            ┌─────────────┐                  │
│                            │ 🖼️ forecast  │                  │
│                            │   .png      │                  │
│                            │  (步骤3产物)  │                  │
│                            └─────────────┘                  │
│                                                              │
│  [💬 返回对话]  [🌿 从步骤2分支]  [📥 导出全部产物]            │
└──────────────────────────────────────────────────────────────┘
```

**交互细节：**
- 每个产物以**卡片**形式悬浮在画布上，支持拖拽重新排列
- 点击卡片可预览内容（图片放大、表格滚动、代码高亮）
- **拖拽交互**：用户可以把步骤 2 的产物卡片**拖拽到输入框**，自动作为新任务的上下文附件
- **分支探索**：对步骤 2 结果不满意，右键卡片选择「🌿 从此处分支」，引擎从步骤 2 重新规划 / 执行，保留原分支在画布左侧作为对比
- **连线编辑**：用户可以手动调整步骤间的依赖关系（高级模式），影响后续规划的 DAG

**价值：** 把「黑盒执行」变成「白盒工作流」，特别适合数据分析、代码生成等多步骤任务。

## 五、具体设计细节补充

### 5.1 输入框交互方案优化

**当前方案：** 顶部拖拽手柄调整高度。

**建议改为：**

> **「自动增高 + 双击展开全屏编辑」** 组合方案：
>
> 1. **正常状态**：输入框随内容自动增高（`min-height: 48px`, `max-height: 160px`），超出后内部滚动
> 2. **全屏编辑**：双击输入框或点击右上角「⛶」图标，输入框**动画展开覆盖整个对话区域**（类似 Notion 的 Focus Mode），此时支持全屏编辑
> 3. **收起恢复**：按 `Esc` 或点击「收起」按钮，平滑动画恢复常态
> 4. **拖拽保留**：保留拖拽手柄作为备选方案，但默认隐藏，hover 输入框顶部边缘时显示

**优势：**
- 更符合现代文本编辑直觉
- 避免手柄与窗口拖拽的冲突
- 减少界面常驻元素，更简洁

### 5.2 颜色与主题规范建议

## 附录：前后端事件扩展建议

为实现上述功能，建议在后端 `events.rs` 中扩展以下事件类型：

```typescript
// types.ts 扩展
interface AgentEvent {
  type: 'tool_started' | 'tool_finished' | 'text_chunk' | 'text_done' 
      | 'status' | 'error' | 'plan_generated' | 'step_started' | 'step_finished'
      | 'thinking_chunk'        // 新增：分层思考片段
      | 'token_update'          // 新增：实时 token 消耗更新
      | 'context_compacted'     // 新增：上下文压缩通知
      | 'memory_recalled'       // 新增：记忆召回通知
      | 'sandbox_status'        // 新增：沙箱状态变更
      | 'artifact_preview';     // 新增：产物预览数据
}

// 新增事件结构示例
interface TokenUpdateEvent {
  type: 'token_update';
  promptTokens: number;
  completionTokens: number;
  stepIndex?: number;
  roundIndex?: number;
}

interface ContextCompactedEvent {
  type: 'context_compacted';
  compactedRounds: number;
  remainingRounds: number;
  reason: 'token_limit' | 'manual';
}
```

> **结语**
>
> 后端引擎已具备业界领先的健壮性（三层流水线、失败降级、沙箱自愈），前端的优化空间主要在于**「把后端的透明度暴露给用户」**——让用户看到 Agent 的思考、记忆、产物流转和错误恢复过程。这不仅是 UI 美化，更是**建立用户信任**的核心策略。
>
> 建议按照 Phase 1 → Phase 2 → Phase 3 的顺序逐步实施，优先解决「用户不知道发生了什么」和「任务失败无法恢复」的痛点，再投入资源做差异化创新。
