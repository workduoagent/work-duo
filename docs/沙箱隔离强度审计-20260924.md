## 二、定性

**当前沙箱 = 运行时环境隔离（依赖/版本隔离），不是 OS 级安全沙箱。**

- 设计意图推断：隔离的是「Python 环境」（防污染用户本机 Python、依赖自动管理）——这一层做得干净（micromamba 便携根 + PathGuard + 审批门）。
- 风险点：`native__run_python_sandbox` 的工具描述自称「内置的**隔离** Python 沙箱」，易被理解为安全边界；agent 系统提示依赖它承载「代码执行都在沙箱内」的安全叙事。**在无人值守（autoToolExecMode）场景下，恶意/失控 prompt 可借沙箱脚本写出工作空间、访问网络、派生进程。**
- 附加发现：**无执行超时**（对比 execute_command 有 60s 硬超时）——长循环脚本既挂死工具又留孤儿进程，属可用性缺口（不依赖安全前提即成立）。

## 四、修复建议（按风险排序，均需 Rust+重启）

1. **执行超时**（可用性，无争议）：run_sidecar 加 tokio timeout（建议 300s 可配 `WD_SANDBOX_TIMEOUT_SECS`）+ 超时 Kill（`_child` 需保留句柄）。
2. **文件系统有界化**（安全）：脚本执行前静态扫描 AST（ast 模块查 open/Path 写目标），非 WORKSPACE 写入直接拒绝；或 WORKSPACE 外写入重定向到虚拟层。
3. **网络默认关闭**（安全）：micromamba run 环境注入 `HTTP_PROXY` 指向无效代理（默认断网），需要网络的用例显式申请。
4. **描述校准**（零成本）：工具描述把「隔离 Python 沙箱」改为「隔离 Python 环境（非安全沙箱）」，避免安全误解。
