# skill-test-case-design · 测试用例设计

> 适用：QA、PM（写验收）、开发（写单测）。用途：从业务规则系统化生成可执行用例，避免只测 happy path。

---

## 何时使用

- PRD/验收标准写完后
- 接口契约冻结后
- 缺陷修复后的回归设计

## 设计方法

| 方法 | 用途 | 例子 |
|---|---|---|
| 等价类 | 有效/无效输入分区 | 页码：正整数 / 0 / 负数 / 非数字 |
| 边界值 | 边界与边界±1 | 最大 100 条导出：99/100/101 |
| 判定表 | 多条件组合 | 会员×优惠券×库存 |
| 状态迁移 | 流程状态机 | 订单：待付→已付→发货 |
| 场景法 | 端到端主备路径 | 下单主路径 / 支付失败回滚 |
| 错误猜测 | 历史坑、注入、空指针 | 空 token、超长字符串 |

## 用例字段

| 字段 | 必填 | 说明 |
|---|---|---|
| ID | ✅ | `TC-<模块>-<序号>` |
| 标题 | ✅ | 一句话可判读 |
| 前置 | ✅ | 账号/数据/环境 |
| 步骤 | ✅ | 可照做 |
| 预期 | ✅ | 可断言 |
| 优先级 | ✅ | P0/P1/P2 |
| 类型 | ✅ | 功能/接口/UI/安全/性能 |
| 验收映射 | ✅ | AC-id |
| 自动化 | | 脚本路径 |

## 覆盖要求（DoD）

1. 每条验收标准至少 1 条正向用例。  
2. **每功能至少 1 条失败/边界用例**。  
3. 接口必须有：成功、参数非法、未授权、资源不存在。  
4. 破坏性/安全：注入、路径穿越、越权、超大载荷（按风险选做）。  
5. 回归：缺陷修复必须带「防再犯」用例。

## 优先级参考

- **P0**：主路径、资金/权限/数据丢失、门禁
- **P1**：常见分支、兼容
- **P2**：美化、极端

## 输出模板

```markdown
# <feature> 测试用例
## 范围 / 不测
## 环境与数据
## 用例表
| ID | 标题 | 前置 | 步骤 | 预期 | P | AC |
## 自动化映射
## 风险与残留
```

## 反模式

- 只写「功能正常」
- 预期结果不可断言（「体验良好」）
- 与验收标准无映射
- 失败用例只写「报错」不写错误码/文案/状态
