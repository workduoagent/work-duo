# 1. ADR 模板

```markdown
# ADR-<编号>: <标题>

| 项 | 内容 |
|---|---|
| 状态 | 提议 / 已接受 / 已废弃 / 已替代 |
| 日期 | YYYY-MM-DD |
| 决策人 | |
| 关联 | PRD / 契约 / 任务 ID |

## 背景
## 决策
## 备选方案
## 后果（正/负）
## 落地事项
## 复审条件
```

**写作规则**：先写清「为什么现在要决」；备选至少 2 个；后果含性能/安全/工期/运维；废弃不删除，标废弃并指向替代项。

# 2. ADR-001: 沙箱语义与宿主工具链

| 项 | 内容 |
|---|---|
| 状态 | 已接受 |
| 日期 | 2026-09-28 |

## 背景

产品提供 Python（micromamba）/ Bun 沙箱，**不提供 Rust/JVM 沙箱**。  
源码审计与 G-M1：沙箱=环境隔离，非 OS 安全边界；`subprocess` 可派生宿主进程。

## 决策

1. 文档与工具描述不称「安全沙箱」，改「环境隔离」。  
2. Rust/Java 检查一律走**宿主工具链包装插件**（`plugin-cargo-check` / `plugin-java-build`）或 `execute_command` 白名单。  
3. 插件禁止 `shell=true` 拼任意命令；子命令白名单。  
4. 无人值守场景对宿主构建命令保持 `sensitive` 审批或显式 allowlist。

## 备选

- 自建 Rust 沙箱：成本高，暂不做。  
- 只允许人工本地跑 cargo：丢失自动化验收能力。

## 后果

- 正：覆盖 Java/Rust 团队；可测可审计。  
- 负：存在调用宿主工具链的攻击面，需靠白名单与审批收束。

## 落地

- `plugin-cargo-check.py` / `plugin-java-build.py`  
- 案例文档 §4.5 宿主工具链

# 3. 契约文件组织约定

## 路径

```text
docs/contracts/
  <feature>-api.md
  <feature>-events.md   # 可选
```

## 文件内结构

1. 元信息（版本、负责人、状态）  
2. 接口列表  
3. 逐接口：请求/响应/错误/示例  
4. 兼容性与迁移  
5. 验收映射

## 引用纪律

- 任务卡 `inputs` 引用契约路径。  
- 测试用例映射契约接口名。  
- 破坏性变更先改契约并升版本，再改代码。

# 4. 数据建模备忘

## 原则

1. 概念清晰优先于表多；避免过早分库。  
2. 主键策略全项目一致（uuid / snowflake / 自增）。  
3. 金额用整数分或 Decimal，禁浮点。  
4. 时间统一 UTC 存储，展示再转。  
5. 软删 vs 硬删写进 ADR。

## 表设计检查

- [ ] 唯一约束与必要索引  
- [ ] 迁移是否幂等（`IF NOT EXISTS`）  
- [ ] 是否双轨（init/updater）同步  
- [ ] 预留扩展字段是否必要  

## 迁移

- DDL 进版本文件，禁止口头改库。  
- 回滚脚本或回滚说明存在。  
- 破坏性迁移需停机/双写方案。
