## 坑：Tauri 窗口 dragDropEnabled 与 HTML5 拖放冲突
- 在 Tauri 中要用前端 `onDrop`+`e.dataTransfer.files` 接文件，必须设 `app.windows[].dragDropEnabled:false`（默认 true）。否则 Tauri 在窗口原生层拦截 OS 文件拖放、吞掉 HTML5 drop 事件，输入框拖文件进去无反应。设 false 后由 webview 自己处理 HTML5 DnD，配合 `onDragOver` 内 `preventDefault()` 即可。改 conf 后需 `npm run tauri` 重编生效。

## Bug 修复：整窗拖拽吸附遮罩松手后不消失
用户报「拖文件进输入框，松手后文件进了输入框底部，但整窗遮罩不消失」。根因：根容器 `agent-chat` 的 `onDragLeave`（把 `dragDepth` 归零、隐藏遮罩）只在**光标离开根容器**时触发；根 `onDrop` 在落点**冒泡到根**时才跑。当文件落在**输入框**内时，输入框 `onDrop` 调了 `stopPropagation()` 阻断冒泡 → 根 `onDrop` 不执行、落点又在根内部不触发 `onDragLeave` → 遮罩卡死（文件已 add 只是状态没复位）。
**修复（typecheck exit 0）**：
1. 输入框 `onDrop` 在 `stopPropagation()` 后就地复位：`dragDepth.current=0; setWindowDrag(false)`（根因修复）。
2. 额外在 `window` 挂 `dragend` 监听做兜底复位（防其他边角落点卡死）。注意：OS 外部文件拖拽的 `dragend` 不在页面元素上触发、故对 OS 文件属 no-op；真正兜住「落在输入框」的是修复 1。
**坑（沉淀）**：凡在子树里 `stopPropagation()` 拦截了根容器的 drop/leave 事件，必须在该子树处理器里**就地复位**根容器依赖的那些状态，否则就是「事件被吃掉、状态永远停在拖拽中」的经典卡死。

## Bug 修复：KaTeX 控制台告警刷屏（中文/en-dash 夹在 $...$ 数学块）
用户报控制台大量 `LaTeX-incompatible input and strict mode is set to 'warn': Unicode text character "回/踩/至/约" used in math mode [unicodeTextInMathMode]` 与 `Unrecognized Unicode character "–" (8211) [unknownSymbol]`，源自 `MarkdownRenderer.tsx` 的 `rehypeKatex` 无参调用→KaTeX 默认 `strict:'warn'` 对「非严格 LaTeX」字符只告警不报错（内容仍正常渲染），模型输出常在 `$...$` 里夹中文/en-dash 导致刷屏。
**修复（typecheck exit 0）**：给 `rehypeKatex` 传选项 `[rehypeKatex, { throwOnError:false, katexOptions:{ strict:false } }]`，`strict:false` 让这些字符按文本静默回退渲染、不再告警；`throwOnError:false` 防真语法错崩掉整段 Markdown。全工程仅此一处 KaTeX 入口（`MarkdownEditor`/`MultiFileViewer` 均复用 `MarkdownRenderer`），一处修全覆盖。
**坑（沉淀）**：AI 输出 Markdown 时 `$...$` 常被误用包裹中文/标点；渲染侧与其在模型侧硬控，不如把 KaTeX 设为 `strict:false + throwOnError:false` 做容错兜底。
