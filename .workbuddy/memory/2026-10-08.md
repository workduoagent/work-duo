## 移除顶栏「首页」菜单项（用户决定）

**用户反馈**：手动测试发现「无论点击哪个菜单，都默认先回到首页」。用户澄清原因：**首页内容还没设计好**，要求先移除首页菜单。

**核查结论**（回读代码 + 逐层确认，**未发现「点任意菜单都跳首页」的代码缺陷**）：
- `src/core/router/index.tsx` 路由表正常，无 `path:'*'` 兜底、无 `<Navigate>` 重定向；
- `TopBar.handleSelect` / `handleChild` 只 `navigate(node.path)`，无强制跳转；
- `AppLayout` 纯布局 + `<Outlet>`，无副作用；
- `dashboard/index.tsx` 无跳转逻辑；
- `routeToTopKey` 的首页分支是**精确匹配** `pathname === ROUTES.dashboard`，
  不会把 `/knowledge` 等误判为首页（此处逻辑本身是正确的）。

⇒ 用户描述的现象**大概率是「首页菜单项在最左侧，视觉上点别的菜单时高亮/滑块仍停在首页」**造成的观感，
  但既然首页未定稿，**移除入口本身是正确处置**（不暴露半成品）。

### 改动（4 处，缺一则出问题）

1. **`TopBar.tsx` MENUS 删除首页项** —— 并在注释里写明「待定稿后如何加回」：
   需同时补回 `lucide` 的 `Home,` import 与 `routeToTopKey` 的分支。
2. **移除 `Home` 图标 import** —— 否则触发 `ts(6133)` 未使用错误。
   ⚠️ 注释里保留 `icon: Home` 的示例文本，ESLint/tsc 不受影响，但**测试断言必须先剔除注释行**再匹配。
3. **`routeToTopKey` 删掉 `if (pathname === ROUTES.dashboard) return 'home'`** —— 🔴 **这是最关键的一处**：
   首页菜单移除后若仍返回 `'home'`，`selected` 会指向**不存在的 key**，
   `measure()` 里 `querySelector('[data-nav-value="home"]')` 返回 null → **滑块静默不定位**，
   且 `if (!top) return` 会让后续路由变化也不更新选中态。改为落到末尾 `return null`。
4. **`dashboard.test.ts` 断言反转** —— 原锁「菜单含首页」（`expect(TOPBAR).toMatch(/key: 'home', label: '首页'/)`）
   改为锁「菜单不含首页」+「其余菜单项完整保留」+「不得return 'home'」。
   断言前用 `codeOnly()` 剔除注释行，否则会匹配到 MENUS 上方注释里的「待加回」示例。

## 智能体向导 步骤4~7 右栏「已编排/已绑定」被挤到页面底部（布局修复）

**用户反馈**（附小屏/全屏两张截图）：智能体新建/编辑页的「配置 MCP、编排 Skill、
本地插件、绑定知识库、绑定服务器」几步样式布局奇怪；小屏下右侧【已绑定 xxx】
面板跑到页面底部去了，**旁边明明还有位置**。

**根因（回读代码定位，非猜测）**：`wizard.scss` 里两条规则的**断点不一致**——
- `&__picker--two`（两栏变体，步骤 4~7 用）折叠断点 = **1100px**；
- `&__picker-aside--right` 有一条 **1280px** 的 `grid-column: 1 / -1`
  （本是为**三栏** `__picker`/MCP 步骤的折叠而设）。

`tauri.conf.json` 的 `minWidth: 1200` ⇒ **1200~1280px 是完全可达的窗口区间**。
该区间内：网格仍是两栏（1fr 260px），但右栏被强制跨满整行 → 掉到主栏下方，
右侧还空着 260px。> 1280px 两条规则都失效/一致 → 右栏正常在右侧 = 用户看到的全屏截图。

**修复**（`src/pages/agent-studio/wizard.scss`，纯 CSS，零 TS 改动）：
1. `&__picker--two` 内新增 `@media (max-width: 1280px) { > .agent-wizard__picker-aside--right { grid-column: auto } }`
   —— 抵消通用右栏规则，使 1100~1280px 仍保持两栏、右栏留在右侧；
   仅 ≤1100px 真折叠成单栏时才落到下方。选择器带 `>` 提高特异性，压过 `.agent-wizard__picker-aside--right`。
2. `&__picker` 补 `align-content: start` —— picker 本身 `flex: 1` 填满内容区高度，
   网格行默认 stretch 会在主栏内容少时把右栏**匀到页面底部**、中间留出莫名空档
   （用户截图里主栏卡片与「已编排」之间那段大空白即此）。
3. 两栏 `1fr` → `minmax(0, 1fr)`，防止 grid 子项内容撑破轨道（与三栏写法统一）。

### 经验
- **断点一致性是这类"布局看起来坏了"bug 的高频根因**：多个选择器各写各的
  `@media`，一旦同元素被多个变体类复用（如 `picker` + `picker--two` 同挂），
  断点不一致就会出现「网格没折叠但子项跨行」的自相矛盾状态。改一处忘另一处 = 复现。
- **回归测试要验证"能抓到这个 bug"**，不能只看修复后全绿——空跑的断言等于没写。
