## F048（长耗时导入进度）—— 三处ImportModal 统一

### 复核：三处忙态实现程度不一
- `SkillImportModal` **连 `importing` 态都没有**（纯 `message.success` 提示），改进最大
- `model-settings` / `mcp` 虽有 `importing`，但只驱动按钮 loading，主体区域**完全静止**
- 沙箱 Python 的 `createWithProgress` 早有成熟形态（阶段+百分比+平滑推进），体验割裂

### 做法：LongTaskProgress（hook + 展示组件）
`useLongTask()` 提供 start / step / easeTo / finish / fail / reset。核心是两件事：
1. **阶段可见**（start/step推 msg）
2. **进度平滑** —— 真实任务常长时间不动（ZIP 解包无法中途报进度），故定时器让进度**缓动逼近**目标（剩余距离越小走得越慢），给出「仍在进行」感知。与沙箱页 startTick/stopTick 同思路，但泛化为可复用 hook。

### 接入细节
- SkillImportModal：拖入/文件夹对话框/ZIP 对话框三处 + catch 全接入；**用户取消对话框时 `task.reset()`**，避免进度条卡在「正在选择…」
- model-settings / mcp：叠加阶段进度，并**补 `catch` 的 `fail`** —— 此前只有 `finally`，失败时进度条会永远停在中途

### 测试抓出的真实缺陷
`aria-valuenow={150}` 未夹取 → 读屏会读出「150%」且宽度溢出容器。已加 `Math.min(100, Math.max(0, ...))`。另一条关键不变量：**卸载后定时器被清理**（否则对已卸载组件 setState）。

**配套一致性**：`__picker-aside--right` 的 `grid-column: 1/-1`（折叠后换行）阈值也是 1100px，**两处必须同步**，只改一处会导致折叠后第三栏与中栏重叠 —— 已写成测试断言。
