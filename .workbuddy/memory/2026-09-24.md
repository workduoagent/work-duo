- **根因**：`useAgentSession` 全部运行态（toolSteps/segments/streamingText/isRunning…）是组件内存状态，切页卸载时 11 个 Tauri 监听全部 unlisten、状态归零；后端 run 独立于 UI 继续，回来后既丢中间事件也不知有活跃 run。且 UI 入口 `run_agent_task` 的 run 不入 run_registry（前端不感知 run_id），无从查询。
- **修法（回放重建，三件套）**：
  1. **Rust**（`commands.rs`）：进程级 `ACTIVE_RUNS` 登记表（agent_id→run_id/session_id/started_at_ms）+ RAII guard 随任务体 Drop 自动摘除（两入口 `run_agent_task`/`run_task_ex` 都登记）；新命令 `get_agent_active_run(agent_id)`、`get_run_replay(run_id)`（复用 #8 per-run 轨迹缓冲：events 含全部事件**除 text/thinking_chunk**（后者以独立累计串 reply/thinking 承载），**含审批/恢复/选择/计划审批挂起事件**）。
  2. **前端 hook**（`useAgentSession.ts`）：把 agent-event 的 200 行内联 switch 抽成 `applyAgentEvent` useCallback，终态/挂起/辅助事件各抽 applyXxx 处理器（监听与回放共用）；新增 `resume(agentId)`：查活跃 run → setRunning(true)+startTaskTimeout → 逐条回放缓冲事件 → thinking/reply 铺底（思考在前、正文在后近似）。**挂起事件仅当它是缓冲最后一条才应用**（其后有事件=决策已处理过，防止弹错窗）。
  3. **页面**（`chat.tsx`）：agent 加载后每 agentId 一次调 `get_agent_active_run` → 有活跃 run 且带 sessionId 则先 `openSession` 回填历史轮次再 `resume`；此后实时事件从重新注册的监听继续流入，与「从未离开」一致。
- **边界**：切页期间 run 已终态 → 查不到活跃 run → 不恢复（DB 轮次已终态回填，正常显示，正是正确行为）；回放失败仅日志（运行态已恢复，实时事件兜底推进）。
