## 第九轮补丁：修 Monaco web worker 加载失败（打开 MCP 详情页报错）
- 现象：进 MCP 详情页报 `Failed to load worker script for label: editorWorkerService` + `Failed to fetch dynamically imported module: http://localhost:1420/node_modules/common/services/editorWebWorkerMain.js`，编辑器区不可用。
- 根因（Vite + monaco ESM 的经典坑）：monaco 的 ESM 构建用 `new URL('...', import.meta.url)` 定位 worker，Vite 不会打包这些路径，于是去请求不存在的 URL。之前只配了 `paths.vs` 指向本地 AMD 包，对 ESM 构建无效。
- 修法：在 `MonacoJsonEditor.tsx` 模块作用域用 Vite 的 `?worker` 导入显式注册 worker —— `import EditorWorker from 'monaco-editor/editor/editor.worker?worker'`、`import JsonWorker from 'monaco-editor/language/json/json.worker?worker'`，再设 `self.MonacoEnvironment.getWorker(workerId,label)` 按 label 分发（`LANGUAGE_WORKERS` 表，默认回落 EditorWorker）。
- 第二个坑：monaco-editor 0.56 的 `exports` = `{"./*":"./esm/vs/*.js"}`，子路径已自带 `esm/vs` 前缀。最初按老教程写 `monaco-editor/esm/vs/editor/editor.worker?worker` → Vite 500 `Failed to resolve import`（拼成 `esm/vs/esm/vs/...`）。去掉 `esm/vs/` 即通。
- 验证方式（未跑 build）：起临时 dev server 于 5199，curl 转换后的模块 → 200 且 worker 导入重写为 `/node_modules/.pnpm/monaco-editor@0.56.0/.../esm/vs/editor/editor.worker.js?worker`（WorkerWrapper 指向 `?worker_file&type=module`），两处 `worker_file` 均 200；`npm run typecheck` EXIT 0。验证后已 kill 临时 5199（用户 1420 的 tauri dev 未动）。
- 副作用：worker 现在由 Vite 打包产出，不再依赖运行时访问 `/node_modules/monaco-editor/min/vs`，生产构建无需额外拷贝该目录。
