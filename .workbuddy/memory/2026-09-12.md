## Skill 编辑弹窗：头像匹配改用 `logo.*` 并按固定优先级择优
- 用户澄清：技能目录里真实的头像文件就是 `logo.svg`（React Admin 模板图，decode 后 `fill="#1677ff"` + 文字 React Admin），不是 `logo.png`。他建议用 `logo.*` 通配匹配更稳妥。
- 根因（上一轮引入的隐患）：`loadFromDisk` 遍历目录遇到 `logo.<ext>` 就**直接覆盖** `logoState`，最终显示的是目录遍历**最后一个**匹配项——机器上 `logo.svg` 排在 `logo.png` 后，于是 SVG 把真头像盖掉；而列表卡片 `readSkillLogoBase64` 是按 `LOGO_EXTS=[png,jpg,...svg]` 固定顺序取首个，两边不一致。
- 修复 `SkillFormModal.tsx`：
  - 导入 `LOGO_EXTS`（`skillFs`）。
  - 头像匹配正则由 `^logo\.(png|jpe?g|gif|webp|svg)$` 改为 `^logo\.[^/]+$`（`logo.*` 任意扩展名，含 svg/ico 等）。
  - 遍历阶段只收集候选到 `logoCandidates: Map<ext,{data,url}>`，循环结束后再按 `logoPriority = [...LOGO_EXTS, 其余非标准扩展名]` 取第一个命中——png→…→svg 位图优先于模板 SVG，且不受目录顺序影响。
- 验证：`tsc --noEmit`（PowerShell 跑受管 node）exit=0 零错误，stdout/stderr 均为空。现 `logo.svg` 这类真实头像文件可正确回显；若日后同时有 `logo.png`（位图）则永远优先于 `logo.svg`。
- 注：`readSkillLogoBase64`（列表卡片）本就按 LOGO_EXTS 取首个、已支持 svg，不需要改，保持两边一致。

## 修复：Skill 导入「选择文件夹」fs 权限 forbidden path
- 现象：桌面端用 `openDialog({directory:true})` 选任意文件夹导入时，`readFolderTree`→`readDir` 抛 `forbidden path: E:\Codes\...\assets\templates, maybe it is not allowed on the scope for allow-read-dir`。
- 根因：`src-tauri/capabilities/default.json` 里 `fs:allow-read-dir` / `read-file` / `read-text-file` / `exists` 的 scope 只放行 `$APPCONFIG/**` 等系统目录变量 globs，不含任意绝对路径（如 E 盘项目目录），故选中目录被拒。
- 修复：在上述四个**读取类**权限的 `allow` 数组首部各追加一条 `{"path":"**"}`（仅读取放开，写入仍受原 scope 约束，导入只把文件写到技能存储目录）。JSON 校验通过（37 条权限）。
- 注意：capability 改动需重新 `npm run tauri`（cargo 重新编译嵌入）才会生效；仅改前端不重编无效。
