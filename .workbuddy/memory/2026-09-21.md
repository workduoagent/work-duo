## 流式滚动抖动热修（2026-09-21 13:5x，用户反馈，tsc 0E，纯前端 chat.tsx）
- **现象**：正文打字机输出时页面抖动——「想往下滚但显示的不是最新内容」；用户向上滚看历史时仍被强行拉回底部。
- **根因（两层）**：①每个流式 chunk 触发一次 `scrollTo({behavior:'smooth'})`（chat.tsx 滚动 effect 无条件执行）——smooth 动画未完成即被下一次打断，多次平滑动画互相拉扯=抖动；②**正文是打字机逐字渲染（滞后于数据流）**，仅靠数据变化触发贴底永远追着实际渲染高度跑，视觉上「总差一截」；③完全没有用户滚动意图检测，回看历史被强拉回底。
- **修复（stick-to-bottom 三件套）**：
  1. **跟随贴底一律瞬时赋值 `scrollTop=scrollHeight`**（禁 smooth），且 rAF 合并（同一帧多次触发只滚一次）；
  2. **流式期间 RAF 循环贴底**：每帧检查容器 scrollHeight，变化即贴底——以**实际渲染高度**为准，数据 chunk 与打字机逐字增长全覆盖；解除跟随/流结束循环即停（不浪费帧）；
  3. **用户滚动意图检测**：`onWheel` 向上滚=立即解除跟随；向下滚回底部附近（<80px）=恢复；`onScroll` 拖动滚动条/触摸板离开底部 >120px=解除、手动回底 ≤8px=恢复（程序贴底自身恒在底部 distance≈0 不误判；内容增长不触发 scroll 事件不误判）；发新提问强制恢复跟随。
- **改动**：仅 `chat.tsx`（followBottom state + scheduleFollowScroll rAF 合并 + RAF 循环 effect + 容器 onWheel/onScroll + handleSend 恢复跟随）。历史回显 restoring 分支保持瞬时定位并恢复跟随。
- **验证**：tsc 0E。真机验收：①发消息看流式回复——页面恒贴最新内容、无抖动；②流式中向上滚——视图稳定停住不被拉回；③滚回底部/发新问题——恢复自动跟随。前端 HMR 即时生效。

### ⚠️ 上条方案作废，最终采用 `allow_directory` API（2026-09-21 23:3x）
- **作废原因**：`add_capability` 的 capability JSON scope 反序列化极严——两种格式都踩 `error deserializing scope: data did not match any variant of untagged enum EntryRaw`：①字符串形式 `"E:/WorkDuo/.skills/**"`；②对象形式 `{"path":"...","acl":{...}}`。`add_capability` 走 `RuntimeCapability::from_str`，其 `EntryRaw` 反序列化比静态 `default.json` 更挑剔，scope 实际**没注入**（`grant_fs_scope` 日志 INFO 成功是假象，fs 校验阶段才抛错）。
- **最终修复（免 dynamic-acl）**：
  - `Cargo.toml` 撤销 `dynamic-acl`（恢复 `tauri = { version = "2", features = [] }`）。
  - `grant_fs_scope` 改用 tauri-plugin-fs 公开 API：`use tauri_plugin_fs::FsExt; let scope = app.fs_scope(); scope.allow_directory(&norm, true)`（递归加入运行时 scope，走插件内部 RwLock，即时生效，无需重编 capability）。权限授予(fs:allow-*) 早已在 `default.json` 静态给出，scope 仅决定「哪些路径允许」，二者职责分离。
  - `if let Err(e) = scope.allow_directory(...)` 捕获错误并 `tracing::warn!`（失败仅跳过该目录，不阻断其他目录）。
