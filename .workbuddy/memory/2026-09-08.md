## 二次修复：成员选择 BUG 仍未彻底解决（用户实测反馈）
- 上一轮「每行过滤其他行已选」仍未能根除「移除后无法再选」。本轮改用**统一已占用集合** `usedAgentIds`（成员 agentId + leaderAgentId + summarizerAgentId）收敛全部 4 个下拉：
  - 顶部「➕ 挑选本地智能体入列」：`allAgentOptions.filter(o => !usedAgentIds.has(o.value))`
  - 成员每行 Select：`... || o.value === m.agentId`（保留本行自身，排除其余角色占用）
  - 主管(leader)/主笔(summarizer)：各自 `... || o.value === 自身值`，并排除成员+另一角色占用（杜绝跨角色重复选）
  - `addMember` 守卫从「仅判成员」扩展为「成员 + leader + summarizer」任一占用即 `message.warning('该智能体已被其他角色占用')` 并拒绝。
- 新增 `agentFilterOption`（按 `searchText=名字+identifier` 匹配）并给 4 个下拉加 `showSearch`，修复 label 为 React 节点导致默认搜索失效的问题。
- 结论：任何智能体不会被选两次；已选中的始终可在本行重选；移除后在任意下拉立即可选。
- `npm run typecheck` 零错误。

## 三次修复：成员选择（labelInValue 彻底解法）
- 用户实测反馈仍坏，并给关键线索「选择框里看到光标」+「选完不该残留 Label」。
- 根因定位：antd 受控 `value` 在 `options` 中找不到对应项时，会把 value 当纯文本渲染并出现文本光标（即用户看到的「光标」）；上一轮为「本行保留显示」把已选项留在 options，既造成用户眼中的「残留」，又在该智能体不在 `agents` 列表时暴露光标。
- 改用 antd **`labelInValue`**：
  - 四个下拉（顶部「➕挑选」、成员每行、主管 leader、主笔 summarizer）`options` 统一 `allAgentOptions.filter(o => !usedAgentIds.has(o.value))` —— 已选中的智能体**从下拉列表彻底剔除**（满足「选完就没了」）。
  - `value={agentValue(id)}` 返回 `{value:id, label: agentMap.get(id)?.name ?? id}`，触发框始终显示**名字**且为 span（无光标），不再依赖 options 里是否存在该项。
  - 加 `allowClear`，改 `onChange` 取 `(v as {value})?.value`。
  - 移除上一轮为节点 label 搜索加的 `showSearch`/`agentFilterOption`/`searchText`（用户反感的「光标」主要来源是搜索框输入态），回归纯单选。
  - 新增 `agentMap`（id→AgentInfo）与 `agentValue` 辅助。
- 结论：选完即消失、触发框干净显示名字无光标、移除/清空后立即可重选、杜绝跨角色重复占用。
- `npm run typecheck` 零错误。

## 修复：LLM 模块连通性测试多模态模型返回 400
- 症状：导入多模态 LLM 在 model-settings 点「测试连通性」返回 HTTP 400「请求格式体不被允许」；同一模型挂到智能体发请求却正常。
- 根因：`src/utils/modelTest.ts` 的 `chatBody()` 写死 `stream: false`。多数 OpenAI 兼容 / 多模态网关只接受流式请求，`stream:false` 直接 400。智能体 `runtime.rs::call_llm_stream_once` 用 `stream:true` 故正常。与用户贴的 `stream:true` curl 自洽（messages 结构本身标准、无问题）。
- 修复：`chatBody()` 改为 `stream:true` 并加 `stream_options:{include_usage:true}`，与智能体真实请求对齐。`probe()` 仅读 `res.status` 判定，流式下状态立即可得，无需改读取逻辑。
- `npm run typecheck` 零错误。

## Bug 修复：模型 JSON 导入报 NOT NULL constraint failed: models.config（1299）
- 现象：模型设置页「导入配置」粘贴 JSON 批量导入时报 `(code:1299) NOT NULL constraint failed: models.config`。
- 根因：`model-mapper.ts::bulkUpsertModels`（导入路径，`model-settings/index.tsx:91` 调用）的 `INSERT ... VALUES` 数组**漏写 `row.app_id` 与 `row.api_secret`**（仅 14 项，列清单 16 项）→ 位置整体错位，`config` 列实际接收到 `row.tags`；导入 JSON 通常无 tags→`row.tags=null`→config 列落 NULL 触发 NOT NULL。单条 `upsertModel`（16 项完整）一直正常，故仅批量导入炸。

## 修复：保存智能体后列表读取崩溃（RangeError: Invalid time value）
- 现象：保存智能体后在 `listAgents()`（`agent-mapper.ts:156` → `rowToAgent` → `new Date(r.created_at).toISOString()`）抛 `RangeError: Invalid time value`，导致智能体列表读不出来。
- 根因：`agent_info.created_at/updated_at` 是 `INTEGER NOT NULL`（epoch 毫秒），但存量库里某行时间字段以字符串/空串形态落库（或 Tauri SQL 插件把整数列按字符串返回），`new Date("…").toISOString()` 判为非法日期 → 抛错。属脏数据触发，与本次保存本身无关（保存写入的是合法 `Date.now()`）。
- 修复：抽出 `src/core/mapper/safeTime.ts` 的 `safeIso()`（兼容 number/纯数字字符串/ISO 串，非法值兜底当前时间），并把 agent/model/knowledge/mcp/squad/skill/agent-session 共 7 个 mapper 里的 `new Date(r.created_at|r.updated_at).toISOString()` 全部替换为 `safeIso(...)`。agent-mapper 原本的本地副本删除、统一引用共享模块。
- 校验：`npm run typecheck` 零错误。铁律已并入 MEMORY 新增坑：DB 时间值一律经 `safeIso()`，禁止裸转。
- 数据归一提示：存量脏时间行在 safeIso 下会显示「当前时间」；重新保存该智能体即可把行时间写回合法 epoch，彻底归一。
