## 修复 InitContext 首启崩溃（no such table: app_config / models）
- 根因：`initDB` 先查 `app_config.first_load` 再跑 `init.sql`，首启时表不存在 → 抛 `no such table: app_config`；`catch` 内 `setDbReady(true)` 又让应用带无表 DB 进场，连锁 `no such table: models`。
- 修复：把「建表」前置——每次启动先幂等 `initTables(db)`（`CREATE TABLE IF NOT EXISTS`+`INSERT OR IGNORE`，已存在则跳过），表就绪后再读 `first_load`、再 `updateTables(db)`；首启后置 `first_load='false'`。彻底消除鸡生蛋问题。
- `init.sql` 头部注释改为「每次启动幂等执行」；《前端开发规范.md》2.12 + `MEMORY.md` 同步该事实（建表必须早于对 app_config 的查询，铁律）。
- 校验：`npm run typecheck` EXIT 0（未跑 build，避免 dist*）。
