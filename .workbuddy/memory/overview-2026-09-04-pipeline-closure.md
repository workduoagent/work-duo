# 修复：流水线把"已成功生成 Excel"误判为未闭环（Desktop/Agent.log · SOL 任务）

## 现象
- 步骤 1「采集 SOL 近一周历史价格」→ 完成。
- 步骤 2「生成 Excel 文档」→ 日志却判 `子任务超过 5 轮未闭环`，步骤 3 未执行。
- 但 `SOL_价格周报.xlsx` 每次都生成成功（10292 / 9412 / 9788 字节，含原始数据/统计/图表），即**产物是对的，判定是错的**。

## 根因（pipeline.rs）
旧循环 `for iteration in 1..=5` 把「终态汇报轮」和「工具轮」混在同一 5 轮预算。
"闭环"要求某轮 LLM 只返回文本（无 tool_calls）才算完成。步骤 2 第 5 轮工具调用刚成功生成
Excel，预算耗尽被循环踢出 → 模型永无机会发"我完成了"的汇报轮 → 误判失败。
这违反了项目既定原则"熔断靠无进展而非砍总轮数"。

## 修复（pipeline.rs，cargo check exit 0）
1. 循环改 `loop`，拆 `round`（总轮，仅日志）与 `tool_iterations`（工具轮，计入预算）；
   **无 tool_calls 的终态汇报轮不计入预算** → 产物已生成必能闭环。
2. `MAX_SUBTASK_ITERATIONS` 5 → 8（工具轮硬上限），给多步子任务余量。
3. 子任务 user prompt 加约束：产物确认生成后立即汇报，勿反复读已掌握数据/重复验证。

## 附带观察（非本次修复范围）
- 步骤 2 第 4 轮模型自写 `exec(open(自身).read())` 触发 RecursionError（白耗一轮），属模型行为；
  本次修复后即便浪费该轮，仍能在第 6 轮正常闭环。
- 日志前半段 ETH 任务用 Deepseek-v4-flash 规划仅回 1 token（completion=1）触发单任务降级且只回
  "我来"——该模型太弱无法规划，非引擎 bug（用户已切 MiniMax-M3，规划正常）。

## 生效
需用户 `npm run tauri` 重编后端。修复后该任务步骤 2 会在 Excel 生成后正常汇报并闭环，步骤 3 预测将执行。
