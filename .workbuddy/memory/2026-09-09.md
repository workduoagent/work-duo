## 排查：Agent 创建项目反复卡授权（verifier 文件类校验 `|` 多候选缺失 · 09-09）
- 现象：用户令 Agent（React 前端开发工程师 + react-developer skill）在 `E:\WorkDuoTest` 建 `oa-web`（Vite+TS+router+zustand+tanstack-query+tailwind+vitest）。运行中频繁需授权，verifier 报「文件应存在且非空：`\\?\E:\WorkDuoTest\oa-web\tailwind.config.js|oa-web\tailwind.config.ts`」失败，自动重试仍失败。
- 实测：`E:\WorkDuoTest\oa-web\tailwind.config.js` **已存在且非空（170 字节）**，全部产物文件均在 → 文件真实生成成功，问题在校验侧，非 Agent 没写文件。
- 根因：`verifier.rs::check_one` 仅 `text_contains` 的 `value` 做了 `split('|')` 多候选容错（verifier.rs:99-106；pipeline.rs:355 注入 prompt 也按「任一即可」渲染）。而 `file_exists`/`file_nonempty`/`directory_exists`/`json_valid`/`text_min_lines`/`excel_row_count` 的 `target` 在 `resolve_path`（verifier.rs:28-37）直接 `Path::new(target.trim())` **未 split**。planner 生成的 success_criteria `target` 含 `|` 候选（绝对路径带 `\\?\` 前缀 + 相对 `.ts` 候选），verifier 把整串当单一含 `|` 的非法路径 → `metadata().unwrap_or(false)` 恒 false → 判未闭环 → 反复重试/卡授权。
- 排除项：`pipeline.rs:548` 传 `ctx.workspace`，但绝对路径 `is_absolute()` 原样保留、不依赖 workspace（**工作目录错配非主因**）；`\\?\` 前缀 Windows 透明、`tools.rs:197` 输出时才去除（**非主因**）；相对候选 `.ts` 即便解析也因扩展名不符失败。
- 修复方向（**待与用户一起改，未动代码**）：`check_one` 各文件类分支对 `target` 同 `text_contains` 做 `split('|')` 多候选，任一满足即通过（`.js` 候选命中即过）；display 路径改为列出命中候选或拼接候选。也可同步约束 planner/SKILL 不生成含 `|` 的 file target（治标，不推荐单独用）。

## 排查 + 修复问题 2：授权等待被 20 分钟兜底定时器误判为后端超时（09-09）
- 现象：授权弹窗挂起、用户去讨论未点 → 底部弹「长时间未收到后端结束信号，任务可能仍在后台运行，可点击「停止」后重新发起」，并 `setRunning(false)` 解禁输入框 → 误点「停止」杀健康任务重发。
- 根因：前端安全兜底 `taskTimeoutRef`（20min，`useAgentSession.ts:337` 启动）不感知 awaiting-approval 暂停态；后端 `approval.rs::suspend` 用 `oneshot` 无限等待、无超时（正确 parked），于是到点必误报。
- 用户结论（设计原则）：**整流程超时不可取**；`isRunning`（发送按钮可用态）只能由后端终态事件 / 用户主动停止翻转，定时器只告警不结束。
- 已修复（代码已改，`npm run typecheck` EXIT=0）：`useAgentSession.ts` 新增 `pendingApprovalRef`+`applyPendingApproval`；定时器回调移除 `setRunning(false)/setIsStreaming(false)/finalizeStuckSteps`，仅非破坏性提示 + `pendingApprovalRef` 护栏；`agent-awaiting-approval` 监听挂起时 `clearTaskTimeout()`+状态「⏸ 等待授权」；`submitDecision` 决策后 `applyPendingApproval(null)`+清状态+`startTaskTimeout()` 恢复定时器。
