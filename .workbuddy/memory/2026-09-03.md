## 排错：打开软件两个运行时崩溃
- **Bug1 [SQL init 崩溃]**：`init.sql` 在 `agent_conversation_session` 上建了引用 `project_id` 的索引 `idx_agent_session_lookup`，但现有库该表已存在（CREATE TABLE 被 IF NOT EXISTS 跳过）、无 `project_id` 列 → init.sql 整段失败 → `updateTables`（含补列 ALTER）未执行 → 后续所有 project_id 读写报 `no such column`。
  - 修复：`init.sql` **移除该索引**（仅留注释），索引改放 `updater.sql` 第 150 行 `ALTER ADD COLUMN project_id` **之后**（第 151 行 `CREATE INDEX IF NOT EXISTS`）。`updateTables` 对首启/非首启都执行（InitContext.tsx:64），故新库/旧库都能正确补列建索引。`npm run typecheck` 通过。
  - 教训：init.sql 只放 CREATE TABLE IF NOT EXISTS，凡引用「可能尚未存在的列」的索引/约束一律进 updater.sql（ALTER 之后），避免现有库整段 init 失败。
- **Bug2 [React Hooks 顺序错误]**：`AgentChatPage` 的 `if (loading) return` / `if (!agent) return null` 早退位于 `sessionTree`/`filteredTree` 两个 `useMemo`（原 1657/1658 行）**之前**；加载态渲染跳过这两个 hook，加载完成后 hook 数量变化 → `Rendered more hooks than during the previous render`。
  - 修复：把两个 `useMemo` 移到早退 `return` **之前**（现 1653/1654 行），所有 hook 在任意 return 前无条件执行。
