## Q1 问题 #2 幽灵产物去重（2026-09-20 10:1x，#2 已实现）
- **根因（澄清旧判断）**：`register_artifacts` 在 pipeline 仅最多调用一次/步（1428 正常闭环 vs 1550 超轮熔断 互斥），故非跨调用重复，而是**单次调用内同物理文件的不同写法判为不同候选**：`merge_artifact_candidates` 按原始字符串去重、`旧 register_artifacts` 按朴素解析路径字符串去重，均无法识别「相对路径 / `.\` 前缀 / 绝对路径 / Windows 大小写不同」指向同一文件 → 各登记一次 + 误报幽灵 WARN（Q1 `登记 2 个产物：memory-v2-lancedb-decision.md, memory-v2-lancedb-decision.md`）。
- **方案（通用性+解耦）**：新增 `resolve_artifact_entries(raw_candidates, ws) -> Vec<(path, is_fallback)>`——解析后按 `physical_key` 判定物理等价去重；同文件重复候选中**真实来源（fallback=false）优先**，升级覆盖 summary 推断重复项（不再误报幽灵）；仅纯 summary 推断命中、无真实来源的同文件才保留 fallback（WARN 仍合理）；不存在文件丢弃（L1 校验）。`physical_key` 折叠 `.`/`..`+空段、统一分隔符、Windows 小写、去 `\\?\` 前缀，纯字符串无 fs 调用、可单测。`register_artifacts` 直接消费其输出，删除旧 `out.iter().any(|a| a.path==path)` 朴素去重（已被物理去重取代）。
- **回归测试 ×5**（cargo 78 passed / 0 failed，原 73 + 5）：`physical_key_unifies_same_file_spellings`（相对/绝对/`.`/`..`/大小写统一同键）、`physical_key_keeps_distinct_files`（异文件不误合）、`resolve_entries_real_beats_summary_same_file`（复现 Q1：相对+绝对同文件只登记 1 次且非兜底）、`resolve_entries_summary_only_keeps_fallback`（纯推断仍标兜底）、`resolve_entries_missing_file_dropped`（不存在文件丢弃）。临时目录按 PID+原子计数器唯一命名，并行安全。
