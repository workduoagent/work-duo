### 智能体两 Bug 修复：SSE 分片解析 + MCP 误用 mcp_id 当 URL（16:43）
用户测试反馈：① Rust 日志大量 `SSE JSON 解析失败：EOF while parsing`；② 调 MCP 网络搜索报 `initialize 请求失败：builder error`，且连弹两次审批。

- **SSE 分片根因**：`call_llm_stream` 旧逻辑对 `resp.bytes_stream()` 的**每个 chunk 直接 `lines()` 解析**。TCP 常把一条 `data:` JSON 行切到多个 chunk（日志 `data={"id": "06e71428f0871` 即半截），半截 JSON 解析即报 EOF。中文 content 若被切在多字节 UTF-8 边界还会变乱码。
  - **修复** `runtime.rs`：改用 `Vec<u8>` 缓冲，累积原始字节，仅处理以 `\n` 结尾的**完整行**；尾行（流结束未换行）单独兜底。新增 `extract_delta_content` 抽 `choices[0].delta.content`，主循环与尾行兜底复用。多字节字符只在整行转 String 时解析，杜绝分片截断。
- **MCP builder error 根因**：`mcp_adapter::McpRemoteTool.execute` 把 `self.server_name`（= `mcp_id`，如 "x-search"）误当作 `endpoint_url` 传给 `call_mcp_tool` → `reqwest` 无法把 "x-search" 构造成 URL → "builder error"。真实连接信息（endpoint_url/protocol_type/headers/auth）在 `mcp_info` 表，旧 `load_config` 没 JOIN 取。
  - **修复**：
    - `mcp_adapter.rs`：`MountedMcpTool` 增 `endpoint_url/protocol_type/headers/auth_type/auth_config` 字段；`McpRemoteTool` 同字段并在 `execute` 透传真实连接；`register_mcp_into` 传入；`execute` 开头加 `[agent] MCP 工具 X 调用：endpoint=… protocol=…` 日志。
    - `commands.rs` `load_config`：MCP 查询改为 `mcp_tool_definition m JOIN agent_mcp_ref r ON r.tool_id=m.id JOIN mcp_info i ON i.id=m.mcp_id`，取出 endpoint_url/protocol_type/headers/auth_type/auth_config；headers 解析为 `HashMap<String,String>`，auth_config 解析为 `serde_json::Value`；加 `use std::collections::HashMap`。
  - **连弹两次审批**：根因是 MCP 调用失败（builder error）→ 模型在下一轮 ReAct 重试同一搜索 → 再次 emit 审批。修好 endpoint 后工具可成功，正常只弹一次；前端 `agent-awaiting-approval` 监听无重复订阅，非双重 emit。

- 根因：`thoughts`/`toolSteps` 是 `useAgentSession` 的**全局状态**，`run` 入口会 `setThoughts([])`（清空上一轮）；而 `chat.tsx` 的 `ThoughtPanel` 仅挂在「最后一条 agent 消息」(`isLastAgent && thoughts.length+toolSteps.length>0`)，故第二轮开始即清掉第一轮、且面板跟着最新消息走，第一轮思考丢失。此前记录为「已知限制」。
- 修复（把思考绑定到每条消息，多轮互不串台）：
  1. `ChatMessage` 新增可选字段 `thought?: string[]` 与 `toolSteps?: ToolStep[]`。
  2. 同步 effect（原仅同步 `streamingText`）改为依赖 `[streamingText, thoughts, toolSteps]`，每次把三者写入「最后一条 agent 消息」；新一轮 `run` 清空全局 thoughts/toolSteps 时，最后一条已换成新轮空的 agent 消息，旧消息因不再是 last 而保留其快照。
  3. 渲染 `ThoughtPanel` 改用 `m.thought`/`m.toolSteps`（按消息自身），去掉 `isLastAgent` 全局门控；仅当该消息自身有思考/工具时才渲染。
- 校验：`npm run typecheck` 0 错误；re-grep 确认三处改动落盘、旧 `isLastAgent && thoughts` 全局渲染已移除。
- 结论：原「已知限制」已消除，多轮每轮的「深度思考」各自可见。
