> ✅ **已完成（2026-10-05）**：报告处方的两条均已落地，并按同一原则扫全了 squad_orchestrator 全部 11 处状态写点——resume-from-pause 加 `AND status='paused'`；`finish_squad_session` 加 `AND status NOT IN ('done','failed','cancelled')`（done×3 尾路径与 DAG 失败收尾同守卫）；三类门禁挂起写（awaiting_plan/checkpoint/delivery）与 paused 写加半终态守卫；checkpoint/plan 批准后的 running 回写加等值守卫（仅 awaiting_* → running）；跨进程 Resume 接管写加半终态守卫。终态一经落定不可被任何迟到写回退/复活，僵尸 running 不再可能。审计脚本确认生产代码无无守卫状态写点残留。内存库单测 3 项锁定 SQL 语义（等值守卫/终态否定/全形态拒绝复活），237 Rust 测试通过。以下为走查时原文存档。

- **证据**：`color: var(--color-muted, #888)`、`color: var(--color-primary, #1677ff)` —— 均未定义，永远吃 fallback
- **未定义清单**（已用 comm 实测）：`--color-primary`、`--color-muted`、`--color-background-soft`、`--color-bg`、`--color-bg-subtle`、`--color-border-faint/strong`、`--color-error`、`--color-info`、`--color-success-border`、`--color-foreground-subtle`、`--color-text`、`--color-text-secondary/tertiary`、`--color-surface(-hover/muted)`、`--color-primary-bg/border/light/soft`、`--color-background-base/hover`、`--color-fill-quaternary`、`--color-hover`、`--color-trace-exec`、`--radius-sm/md/lg`
- **影响**：因为都写了 fallback，编译不报错、视觉不炸，缺陷被完全掩盖 —— 但换主题时这批文字**永远不会变色**，且 fallback 是 antd 旧默认蓝 `#1677ff`，与项目 Ocean 调色板 `#0ea5e9` 不一致 → **chat 页与其它页面存在两套主色**。
- **改造**：`variables.scss: root` 补齐映射（`--color-primary: var(--color-brand-600)`、`--color-muted: var(--color-foreground-muted)` 等），然后全局删 fallback。

### 3.2 `chat.scss` 用 `.dark &` 嵌套写死深色字面量
- **位置**：`chat.scss:32-33/67-70/273-274/434-441/595-601/...`（14 处）
- **证据**：`.dark & { background: #1a1a1a; border-color: #2f2f2f; }` —— 旧深色主题遗留字面量，绕过令牌体系
- **影响**：IDE 主题为 light 时不生效，但代码里同时存在未定义令牌 → 主题切换时"半跟随半固定"。`chat.scss:274/924` 的 `color: #aaa` 在浅色下若命中即 2.0:1 对比度，远低于 WCAG AA 4.5:1。
- **改造**：全部替换为 `var(--color-background-subtle)` / `var(--color-border)`（令牌已含 `.dark` 变体，不需要重复适配）。

## 3.5 值得保留的设计（亮点）

1. **设计令牌体系认真维护**：`variables.scss` 374 行、56 个语义令牌 × 5 套主题，连 highlight.js 的 17 个语法色都做了亮/暗双份。`border-radius` 与 `font-size` 100% 令牌化（0 处 px 圆角、0 处 px 字号），这在同规模项目里少见。
2. **通知体系是全项目最完整的部分**：`useNotify()` + `notifyBridge` 双层设计，完美解决「全局事件跑在 React 之外也要弹提示」这个真实难题。`result(res, okText, failPrefix, silentOk)` 的 `silentOk` 甚至内建了「写盘成功后不弹 toast」的产品原则。
3. **重量依赖懒加载非常专业**：`MultiFileViewer` 一个组件对 7 种格式全部动态 import，mermaid/echarts 走 promise 单例缓存。
4. **沙箱 Python 的进度反馈是全项目最佳交互**：pct 缓动 + 真实阶段文案 + error 分支，而非转圈。
5. **`SquadDetailPage` 的 memo 化与定时器清理是范式级代码**（5 个 memo、7 处 setInterval 全带 cleanup）—— 团队**具备**拆巨型组件的能力，只是没用在这个文件上。
6. **windowed 轮询的注释式取舍**：`// 后台协作实时徽标：轻量 SQL 轮询（不动列表 loading）` —— 明确选择「不打扰用户」，取舍写在代码里。
