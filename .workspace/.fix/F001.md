## 方案 v2 · 信任协议（类蓝牙配对，2026-10-02 用户定案）

> 方向变更：不做单一全局 Token。产品目标是**跨设备互通**（多个可信设备而非一个密码），采用配对制；监听地址改为可配置支持 0.0.0.0。

1. **监听地址可配置**（`app_config.mcp_bind_addr`）：`127.0.0.1`（默认）/ `0.0.0.0`（内网互通）。切到 `0.0.0.0` 时**强制启用配对信任**：无已配对设备则拒一切非本机请求。注意 Windows 防火墙首次放行提示。
2. **配对流程（类蓝牙）**：设置页「配对新设备」→ 配对模式 2 分钟有效并显示 6 位配对码 → 新设备 `POST /pair` 带设备名 + 配对码 → 码验证通过签发**设备专属 Token**（256-bit 随机，服务端只存 SHA-256 哈希）。防爆破：窗口期外拒绝、尝试 ≤5 次锁定。
3. **请求鉴权**：`Authorization: Bearer <device_token>`，按哈希查表校验，命中放行并记 last_seen。标准 MCP 客户端（ZCode/Cursor/Claude Code）的 mcpServers 配置均支持自定义 headers——**配对是 UX，设备令牌是凭证**（同构蓝牙：配对码=PIN、设备列表=已配对设备、吊销=取消配对）。
4. **设备管理 UI**：已配对设备列表（名称 / token 指纹前 8 位 / 最近活跃），支持重命名与吊销，吊销即时生效。
5. **本机零摩擦**：绑 127.0.0.1 时可开「本机信任」——本机编码工具经只读 token 文件（`%APPDATA%/com.workduo/`，用户级 ACL）取默认设备 token，免配对。
6. **附加防线**：Origin 校验（浏览器页面无 token 且 Origin 可疑一律 403，兼防 DNS rebinding）；配对与调用全链路 `fe` 日志留痕。

## 已知权衡（诚实记录）

- 局域网为**明文 HTTP**，Bearer 可被同网段嗅探——缓解：设备令牌随时吊销、权限仅限驱动 Agent；后续可选 TLS / 反代加强。
- **方案 B（后续增强）**：配对改交换 Ed25519 公钥、每请求签名（method+ts+nonce 防重放防嗅探）——标准 MCP 客户端不支持签名，仅对第一方客户端有意义，先落 v2 再评估。
