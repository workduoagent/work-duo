# F007 · runtimeStore 事件路由无 run 归属校验

- 来源：[20261002 全项目走查](./20261002-走查报告原文.md) §1.7
- 位置：`src/pages/agent-studio/session/runtimeStore.ts:574-578`
- 级别：P0 致命·正确性
- 状态：**已修复并冒烟（2026-10-03）**

## 问题与影响

所有事件无条件写入「当前 running 会话」；切换会话后第二个 beginRun 覆盖 runningSessionId，前一 run 的终态事件写入新会话条目，UI 显示错乱。

## 修复方案（已实施 · emit 汇聚点统一盖章）

发现基建现成：run spawn 顶层已有 `set_trace_context(run_id, agent_id, session_id)`（台账 D4）+ `with_run_id_scope` task_local——session 无需穿参。

1. **Rust（events.rs）**：新增 `current_session_id()`（按 current_run_id 查 trace 上下文）；`emit()` 汇聚点统一盖 `sessionId` 戳——36 个事件函数（agent-event 流/终态/token/approval/recovery/choice/plan-approval/artifact…）零签名改动全覆盖；`emit_task_error` 载荷从裸字符串升级为 `{message}` 对象（戳由 emit 盖）；
2. **前端（runtimeStore.ts）**：`route` 升级归属路由——带戳事件路由到**归属会话条目**（优于丢弃：终态定稿/审批卡不丢），无戳回退既有「正在运行会话」行为；`agent-task-done/error` 的 `endRun()` 条件化（外来终态不得清掉当前运行的追踪）；
3. **类型**：AgentEvent/ApprovalRequest/RecoveryRequest/ChoiceRequest/PlanApprovalRequest + sessionId?: string；task-error 载荷对象化同步前端监听器。

## 验证

双会话并发 run 时事件各归各会话，切换无串扰。
