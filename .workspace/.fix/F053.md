# F053 · Node 沙箱页「运行脚本」原地执行报 JSError（F002 验证过程中发现）

- 来源：F002 实机点验（2026-10-03，UIA 驱动沙箱页真实操作）
- 位置：`src-tauri/src/bun_manager.rs` run_node_script → run_script_with_selfheal / run_bun_sidecar_policy
- 级别：P1 严重·功能（Node 沙箱管理页运行功能对 bun_root 之外的脚本不可用）
- 状态：**待修复**

## 问题与影响

设置 → 沙箱环境 → Node 页「运行脚本」弹窗，对任意 bun_root 之外目录的 .js 脚本（含工作空间内）执行报：

```
脚本执行失败（退出码 1）：
Error occurred loading entry point: JSError
```

**已排除的因素**：
- 脚本本身：`console.log(...)` 单行，bun CLI 直接执行同一文件成功；
- 路径传递：UIA 读取弹窗输入框确认路径正确（绝对路径、.js）；
- F002 边界：同路径在边界校验后**放行**（越界路径才报越界错误），错误发生在 bun 启动执行阶段；
- 同路径 + 应用同款参数的 CLI 复现：`bun --preload <guard.js 绝对路径> <脚本>` + cwd=脚本目录 + WD_SANDBOX_FS_GUARD/WS → **成功**输出 hello。

**尚未对齐的疑似差异**（修复时排查方向）：
- 应用注入的其余 env：BUN_INSTALL/BUN_CONFIG_REGISTRY/NODE_PATH/net 代理组（127.0.0.1:9）——CLI 复现未全量带上；
- preload guard.js 在 app 进程上下文中的行为（`Error occurred loading entry point: JSError` 是 bun 对 preload/入口 JS 抛错的报错形态）；
- 插件通道（plugin-md-toc 同日实测）Bun 执行正常——对比 plugin_runner 与 run_node_script 的 spawn 差异是最短路径。

## 修复方案

1. 对比 plugin_runner 的 bun spawn（该通道已验证可用）与 run_bun_sidecar_policy 的 env/args 差异；
2. 定位后修复，使 Node 沙箱页对允许根内脚本可正常执行；
3. 补一条集成回归（沙箱页运行 bun_root 外脚本）。

## 验证

- Node 沙箱页运行工作空间内 .js → stdout 出现预期文本；
- 运行越界脚本 → 仍报 F002 边界错误（确保修复不破坏 F002）。
