## 全仓 fs 消费面扫描结论（2026-10-03）

fs 插件全仓仅 5 个消费文件，收敢单极小：

| 消费文件 | 路径来源 | 收敛后归属 |
|---|---|---|
| `kbFs.ts` | KB 根目录（默认 $APPDATA 或迁移自定义目录） | 静态默认 ∪ fsScopeBootstrap 启动授权 ✓ |
| `skillFs.ts` | Skill 根目录（同上） | 同上 ✓ |
| `export-file.ts` | 保存对话框选的位置（写） | 写权限本就无 `**`、已按标准目录放行（现状不变） |
| `SkillImportModal.tsx` | **用户手选 ZIP**（读） | 唯一缺口：对话框选完后补一次运行时授权（1 处） |
| `message-ui.tsx` | 聊天文本中的图片路径（读） | 工作空间内 ✓；越界路径读取失败 → 已有文件卡兜底（正确行为） |

对话框 `open()` 调用点 5 处（沙箱×2/工作空间/导出目录/迁移目录）——多为选目录或路径走 Rust 命令，无需 fs 读权限。

**基建确认**：`fsScopeBootstrap.ts` 启动时已为 skill_path/knowledge_base_path/vector_path/plugin_path 动态授权（迁移目录已覆盖）——**缺口仅一处：workspace_path 不在其清单**，需补（聊天图片卡等工作空间读依赖它）。

## 问题与影响

webview 无 CSP 约束，注入脚本可直接调 Tauri IPC 读 ~/.ssh、Cookie DB 并经 http:default 外传。注意 Rust 侧 PathGuard 不覆盖前端 fs 插件调用，两套边界互相独立。

## 修复方案

设严格 CSP（default-src 'self'; script-src 'self'）；fs 权限从 ** 收敛到 $APPDATA/** 等实际需求路径（需同步排查 kbFs/skillFs/export 的真实读写范围）。

注入脚本读 $HOME 敏感文件被拒；知识库/技能/导出功能全量回归通过。
