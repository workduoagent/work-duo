# skill-code-review-checklist · 代码评审清单

> 适用：`review-code-critic`、架构、资深开发。用途：四维评审；输出分级意见。**评审不改代码。**

---

## 何时使用

- PR/分支合并前
- 小分队 S4/评审节点
- 交付前 Blocker 扫描

## 四维清单

### 1. 正确性

- [ ] 逻辑与需求/契约一致
- [ ] 边界、空值、并发、重入
- [ ] 错误处理完整且不吞错
- [ ] 事务/幂等/重试语义正确
- [ ] 资源释放（文件、锁、连接）

### 2. 安全

- [ ] 注入（SQL/命令/模板/XSS）
- [ ] 路径穿越与任意文件读写
- [ ] 认证/授权检查完整
- [ ] 敏感信息不进日志/仓库
- [ ] 反序列化、SSRF、不安全反序列化
- [ ] 第三方依赖风险

### 3. 可维护性

- [ ] 命名、职责单一、无复制粘贴蔓延
- [ ] 公共能力正确抽象（不过度设计）
- [ ] 错误信息可排障
- [ ] 测试与代码同步变更
- [ ] 与 `skill-eng-standards` 一致

### 4. 性能

- [ ] N+1 查询、无界循环/无界列表
- [ ] 大对象与重复计算
- [ ] 超时、并发上限、缓存策略
- [ ] 前端：不必要重渲染、大包

## 输出分级

| 级别 | 含义 | 门禁 |
|---|---|---|
| Blocker | 正确性/安全/数据丢失/门禁失败 | 必须修复 |
| Major | 高风险设计缺陷、明显性能坑 | 应修复 |
| Minor | 可维护性、小性能 | 建议 |
| Nit | 风格、命名 | 可选 |

## 意见格式

```text
[Blocker] file:line — 问题一句话
影响：… 
建议：…（可执行，不代改）
```

## 通过条件

1. 无未清 Blocker。  
2. Major 有处理结论（修或书面接受）。  
3. **即使通过也要列出检查过的维度**（防假通过）。  
4. 评审员工具面禁止 `write_file` / `edit_file` / 执行类。

## 反模式

- 「LGTM」无维度说明
- 顺手改代码（越界）
- 只纠结空格不看安全
- 无 file:line 的空泛批评
