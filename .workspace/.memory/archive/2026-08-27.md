## 连通性测试判定修复（HTTP 405 误报成功）
- **根因**：`src/utils/modelTest.ts` 原逻辑 `if (res.status < 500) ok:true`，导致 HTTP 405（Method Not Allowed）也判为「连通成功」。实际 405 说明服务端可达但只接受 POST（GET 探测被拒），并非成功。
- **修复**：按状态码细分——2xx=成功；3xx=重定向可达；401/403=鉴权失败；404=接口路径不存在；405=接口不支持 GET 探测（网络可达但需 POST）；其他 4xx=请求被拒；5xx=服务错误；catch=连接失败/超时。UI 维持 `result.ok?'ok':'fail'` 二态，405 现进入 fail 态并显示准确文案（tooltip=result.message）。
- **局限提醒**：当前为纯前端 GET 探测，OpenAI 类 `/v1/chat/completions` 仅接受 POST，GET 必得 405/404；要真实验证「连通+鉴权+模型可用」需 Tauri 侧 `@tauri-apps/plugin-http` 实现 test_model（POST 最小请求体）经 core/ipc 调用（modelTest.ts 已留注释说明）。
- 校验：`npm run typecheck` EXIT 0（未跑 build）。

## capabilities 修坑：http:default 的 url `*` 非法
- **报错**：`error deserializing scope: \`*\` is not a valid URL pattern: a relative input without a base URL is not valid`（Tauri 启动期反序列化 capabilities 时报）。
- **根因**：`capabilities/default.json` 里 `http:default` 的 `allow` 写成 `{ "url": "*" }`。Tauri2 的 plugin-http scope 要求**带 scheme 的完整 URL 模式**，`*` 单独出现被解析成相对路径 → 报错。
- **修复**：改为 `{ "url": "https://*:*" }` + `{ "url": "http://*:*" }`（schema 的 global_scope_schema 明确示例：`https://*`=443 端口、`https://*:*`=任意端口；用 `*:*` 覆盖内网非标准端口如 `:8000`）。JSON 已校验合法。
- **生效方式**：capabilities 是运行时由 Tauri 从 `src-tauri/capabilities/` 读取的配置文件，**重启 `npm run tauri` 即可加载，无需 `cargo build`、更不碰 vite build**。
- **经验**：任何 Tauri 插件权限的 scope URL 都不能裸写 `*`，必须用 `https://*`（或带端口 `https://*:*`）；fs 的 path 用 `$APPDATA/**` 这类宏路径不受影响。
