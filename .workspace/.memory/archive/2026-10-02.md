### Mermaid 校验方法（可复用）

Windows 下 README 是 **CRLF 行尾**，提取 ```mermaid 块的正则必须写 `/\r?\n/`，否则匹配数为 0（`\n` 不生效，极易误判「文档没有图」）。

node 环境无法直接 `mermaid.parse()`，两难：设 `globalThis.window = globalThis` → DOMPurify 走浏览器分支但无真实 DOM → 报 `DOMPurify.addHook is not a function`；不设 window → mermaid 报 `window is not defined`。且该仓库未装 jsdom/happy-dom/linkedom（依项目铁律不得自行安装依赖）。**结论：改用静态结构校验**（括号/引号配平、subgraph-end 配对、节点定义 vs 连线引用一致性）。

写这类校验器自身的两个坑（都已实际踩到）：
1. **剥离顺序**：必须先 `replace(/\|[^|]*\|/g,' ')` 再剥引号。反序会残留空管道 `"| LIB"`，导致该节点正则抓不到 → 引用数少算（实测 8 变 7，若正好无其他引用则会漏报 missing）。
2. **节点声明正则要覆盖全部形状**：`[方] ([圆角]) ((圆)) {菱形} {{六边}}`，漏 `{` 会把合法菱形节点误报为「未定义」（实测 GATE 误报）。
→ 教训：**校验器「通过」之前必须先证明它能抓错**，否则只是虚假信心。
