## 紧急 Bug 修复：micromamba 落到 AppData（用户反馈脚本执行报 prefix 不存在）
- 现象：`run_python_script` 报 `critical libmamba The given prefix does not exist: "C:\Users\Administrator\AppData\Roaming\mamba\envs\default"`。
- 根因 1（致命）：所有命令把全局选项 `--root-prefix`/`--rc-file` 写在子命令**之后**；对 `micromamba run` 尤其写在 `python <脚本>` 之后，被当作「传给 python 的参数」而完全失效，micromamba 回退到**内置默认根前缀**（AppData/Roaming/mamba），根本没用到我指定的程序目录。已用真实 `micromamba.exe` 跑了一组对照：正确顺序（globals 前置）micromamba 正常读配置；旧顺序（globals 后置）即复现 AppData 回退——证明确为此因。
- 根因 2：根目录之前用 `current_exe().parent()`（程序目录），未严格按用户反复强调的走 **`$RESOURCES`**。
- 修复（`mamba_manager.rs`）：
  - 新增 `global_args(mamba_root, rc)` helper，统一构造 `--root-prefix <mamba_root> --rc-file <.mambarc>`，**强制前置**于子命令；全部 8 个命令（init/list/install/remove/reset/run/build_env_info/ensure_default_env）改用「先 global_args 再 extend 子命令+参数」。
  - `base_dir()` 改为 `app.path().resource_dir()`（即 `$RESOURCES`，随包迁移），获取失败回退 `current_exe().parent()`；二者均不落 AppData。需 `use tauri::Manager;`。`MambaManager` 改为空结构体（`new()` 不再存 base_dir），`setup(&self, app)` 签名新增 `app: &AppHandle`。
  - 路径布局变为 `$RESOURCES/mamba_root/envs/<env>`；`.mambarc` 落在 `$RESOURCES/.mambarc`。
- 校验：`cargo check` 零错误零告警；并用真实 sidecar 二进制验证 arg 顺序修复有效。
- 提示用户：旧位置若残留 `mamba_root`（程序目录或 AppData 下）为孤立目录，可手动删除回收空间；新 `default` 环境会在 `npm run tauri` 重启后于 `$RESOURCES/mamba_root` 自动重建。

## 紧急 Bug 修复：run_python_script 中文路径报 `'okens' is not recognized`（Windows cmd 编码）
- 现象：运行脚本报 `脚本执行失败（退出码 1）：'okens' is not recognized as an internal or external command...`（cmd 特征报错）。
- 根因：**`micromamba run` 在 Windows 上经由 `cmd /C` 外壳执行命令**。当脚本路径含中文等非 ASCII 字符时，路径被拼入 cmd 命令行后因编码问题被拆坏，导致激活阶段设置环境变量（如 `set PYTHONUTF8=`、`set PYTHONIOENCODING=`）的命令碎片被当成命令执行 → 报 `'okens'`/`'OENCODING'`/`'TF8'` 这类错。纯 ASCII 路径（建环境/装依赖/跑 ASCII 脚本）完全正常，故此前未暴露。
- 验证：用真实 `micromamba.exe` 复现——脚本路径带中文时稳定抛出 `'OENCODING' is not recognized`/`'TF8' is not recognized`；而**直接 spawn 环境内 `python.exe`（CreateProcess，原生 Unicode）跑同一中文路径脚本 100% 正常**（PREFIX/pip 解析正确），证明根因在 micromamba 的 cmd 外壳而非路径本身。
- 修复（`mamba_manager.rs`，不改 capability、不复刻激活环境）：在 `run_python_script` 内把用户脚本**复制到纯 ASCII 临时文件** `$RESOURCES/mamba_root/run_tmp/__sandbox_run_<纳秒时间戳>.py`，用该 ASCII 路径喂给 `micromamba run`；同时把**工作目录设为原脚本所在目录**（经 `run_sidecar` 新增的 `cwd: Option<&Path>` 参数 → `cmd.current_dir()`，CreateProcess 原生 Unicode 安全），保证脚本内相对文件操作仍按原路径解析。运行结束（无论成败）`remove_file` 清理临时文件。
- 取舍：临时副本位于 `run_tmp`（全 ASCII），因此脚本若用「相对 import 同目录其他 .py」且原目录含中文时会解析不到（需改 `sys.path`/`PYTHONPATH`，而 PYTHONPATH 带中文会重新触发 cmd 编码坑，故未做）；单文件脚本、相对数据文件读写均正常。这是当前最稳方案——比绕过 micromamba 直接 `command(python.exe)`（需放开 `shell:allow-execute` 非 sidecar 权限 + 手动拼 PATH/DLL 激活）风险更低。
- 校验：`cargo check` 零错误零告警；端到端复现中文路径脚本成功运行 + CWD 正确切回原中文目录（marker 文件落在原目录）。
- 经验复用：后续接入 Node.js 运行时若也走任意「经 cmd 外壳 + 含中文参数」的执行路径，须引以为戒，优先用 CreateProcess / ASCII 临时副本思路。

## 钻取动画卡顿修复（点击百宝箱进入二级菜单延迟卡顿）
- 用户反馈：点击【百宝箱】进入二级菜单时动画延迟、卡顿。
- 根因三叠加：
  1. **React 每帧重渲染（主因）**：钻取时 `setTracking(true)` 开 rAF 循环（原 TRACK_MS=900ms），每帧 `measure()` 调 `setThumb` → 每帧 setState → TopBar 全量重渲染，主线程被 React 调和抢占、掉帧。
  2. **布局属性动画重排**：`pillChildIn/Out` 同时动画 `max-width`+`padding-inline`（layout-triggering），4 项错峰播放每帧重排。
  3. **整体时长偏长（0.7~0.9s）**：给人延迟感。
- 修复：`TopBar.tsx` 把 `thumb` state 改为 `thumbRef`，`measure()` 直接 `thumbEl.style.setProperty('--pill-x/--pill-w')` 直写 CSS 变量（去掉每帧 setState，保留 rAF 精确跟随）；常量 `CHILD_ANIM_MS 500→320`、`CHILD_STAGGER_MS 80→50`、`TRACK_MS 900→480`；移除 `ThumbRect` 接口与 `CSSProperties` 导入。`layout.scss`：`pillChildIn/Out` 改为纯 `opacity+transform`（去 `max-width/padding`，零重排，宽度由 flex 自然排布）；thumb/slot/back 过渡 0.5~0.55s 统一缩到 0.32s。
- 校验：`npm run typecheck` 零错误。纯前端 / CSS-only，前端 HMR 即生效（无需 tauri 重编译）。
