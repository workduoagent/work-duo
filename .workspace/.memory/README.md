## 目录结构

```text
.workspace/.memory/
├── README.md              ← 本文件：目录说明与接续指引
├── MEMORY.md              ← 【必读】长期约定、技术栈、铁律、红线
├── CURRENT.md             ← 当前进行中（跨工具接续入口，每轮刷新）
└── archive/
    ├── 2026-*.md          ← 逐日流水（43 个文件，2026-08-26 ~ 10-09）
    └── topics/            ← 跨日期的专题总结（4 个 overview 文档）
```

**分层意图**：`MEMORY.md` 管「永远不变的约定」，`CURRENT.md` 管「正在变的状态」，`archive/` 只作查证材料。**约定不要写进 CURRENT，进度不要写进 MEMORY。**

## 迁移说明（2026-10-09）

本目录由原 `.workbuddy/memory/` 迁入。

**为什么迁**：`.workbuddy/` 是客户端私有目录，随客户端/设备变动，不便携带。改为提交进仓库后，**git pull 即可在任意设备获得完整记忆**。

**迁移内容**：
- 42 个逐日文件 → `archive/`（**全量MD5 校验：41 个字节级一致，1 个为预期的合并扩充**）

- 两份内容不同的 `2026-10-02.md`（客户端版 75 行 + 项目版 25 行）→ **合并为96 行完整日志**（六节，涵盖源版全部 6 个小节 + 项目版内容），未丢任何内容
- 4 份历史设计文档 → `.workspace/.future/history/`（改语义化文件名）
- **`.workbuddy/` 目录已彻底删除**（2026-10-09 用户确认），git 历史中仍可恢复：`git checkout <commit> -- .workbuddy/`

**数据校准原则**：迁移时对过时数字做了实测修正，均标注校准日期；无法核实的一律标「未确认」，不猜。

2. 对差异文件额外核对小节标题清单，确认是「编号化重组 + 扩充」而非内容丢失

## 维护约定

| 动作 | 规范 |
|---|---|
| 写约定 | 只写进 `MEMORY.md`，带日期 + 来源，冲突时以最新实测为准 |
| 更新进度 | 刷新 `CURRENT.md`（含残项、基线、下一步、环境事实） |
| 记流水 | 新建 `YYYY-MM-DD.md`；跨日期专题另建 `archive/topics/xxx.md` |
| 改铁律 | 必须是「踩过坑 → 归纳成规则」，不写空泛的正确废话 |
| **判断残项** | **必须回读函数体核实**，不能只数定义处，也不能只信文档陈述 |
| **多路并行走查** | 结论必须抽样人工复核；标「致命/严重」的必须回读代码确认 |
